# 에이전트로 시작하기

**30분이면 됩니다. 강사가 필요 없습니다.**

이 문서는 [hands-on.md](hands-on.md)와 다릅니다. 그쪽은 강의용이고 커맨드를 직접 칩니다. 도구가 무엇을 강제하는지 눈으로 보려고 그렇게 합니다.

여기서는 **에이전트에게 말로 시킵니다.** 실무에서 실제로 쓰는 방식입니다. 커맨드를 외울 필요가 없고 대신 **어디서 당신이 결정해야 하는지**를 알아야 합니다. 그것이 이 문서의 내용입니다.

전제는 둘입니다.

- 셸이나 MCP를 쓰는 에이전트. Claude Code, Cursor 등
- `engram` 설치. `go install github.com/neocode24/engram/cmd/engram@latest` 또는 `brew`

설치는 [hands-on.md](hands-on.md) 1단계에 자세히 있습니다.

## 1. 에이전트에 붙입니다

두 가지를 붙입니다. 하나는 **문서**이고 하나는 **도구**입니다.

### 문서. 에이전트가 규약을 읽습니다

```
engram skills install
```

```
심었습니다. 파일 1개
  /Users/<당신>/.claude/skills/engram/SKILL.md
에이전트를 다시 시작해야 스킬이 잡힐 수 있습니다
```

`--dir` 없이 치면 홈 디렉토리에서 **실제로 있는** 에이전트 스킬 디렉토리를 찾아 전부에 심습니다. 없는 도구를 위해 디렉토리를 만들지 않습니다. 하나도 못 찾으면 실패하니 그때는 `--dir`로 직접 줍니다.

이 문서에는 임계값이나 허용값이 없습니다. **그 위키의 규칙은 에이전트가 `rules show`로 물어봅니다.** 그래서 한 번 심으면 위키가 여럿이어도 통합니다.

### 도구. 에이전트가 위키를 부릅니다

셸을 쓰는 에이전트는 이 단계가 필요 없습니다. 커맨드를 그냥 칩니다.

MCP만 쓰는 클라이언트는 등록합니다. Claude Code 기준입니다.

```
claude mcp add engram -- engram mcp --wiki ~/my-wiki
```

**위키 경로를 등록할 때 고정합니다.** 도구는 경로를 인자로 받지 않습니다. 받으면 에이전트가 아무 디렉토리나 읽을 수 있습니다.

MCP로 붙으면 1절의 스킬 문서가 **프로토콜로도 전달됩니다.** 서버가 접속할 때 그 문서를 지시로 함께 내므로, 스킬 디렉토리를 안 읽는 클라이언트도 같은 규약을 받습니다. 그래서 셸을 쓰든 MCP를 쓰든 에이전트가 아는 규칙이 같습니다.

전사까지 쓰려면 서버를 하나 더 등록합니다. 선택입니다.

```
claude mcp add engram-voice -- engram-voice mcp
```

도구가 열입니다.

```
backlinks, bridge, capture, digest, lint, recall, resurface, rules, search, status
```

**목록을 한 번 보세요.** `promote`가 없습니다. 왜 없는지는 7절에 있습니다.

## 2. 위키를 만듭니다

```
engram init
```

```
위키를 초기화했습니다: . (프리셋: personal)

디렉토리:
  inbox/       새 자료가 들어오는 곳
  sources/     원본을 보존하는 곳
  context/     정리된 문서가 사는 곳
  archive/     승급에서 물러난 문서가 가는 곳
```

**디렉토리 넷이 분류함이 아닙니다.** 주제별로 나눈 것이 아니라 **성숙 단계**입니다. 같은 지식이 `inbox`에서 시작해 `context`로 올라갑니다. 이 하나만 이해하면 나머지가 따라옵니다.

git 저장소로 만들어 두면 이력이 남습니다. 필수는 아닙니다.

## 3. 넣습니다

**에이전트에게**

```
회의-전사.txt 를 위키에 넣어 줘.
```

에이전트가 `capture`를 부릅니다.

```
inbox에 넣었습니다: inbox/2026-08-22-회의-전사.md
다음: 문서를 정리한 뒤 승급하세요
```

**여기서 아무것도 검사하지 않습니다.** 형식도 길이도 보지 않습니다. 관문은 올라갈 때 한 번이면 되고, 넣는 자리에까지 관문을 두면 사람들이 아예 안 넣습니다.

그러니 망설이지 말고 넣으세요. 슬랙 로그, 회의 전사, 읽은 글, 반쯤 쓴 메모 전부 됩니다.

**요약해서 넣지 마세요.** 에이전트가 요약하려 하면 원문 그대로 넣으라고 하세요. 무엇이 중요한지는 나중에 알게 되고, 그때 원문이 없으면 되돌릴 수 없습니다.

## 4. 올립니다. 여기가 당신 자리입니다

**에이전트에게**

```
inbox 에 있는 것 중에 context 로 올릴 만한 걸 골라서 제안해 줘.
```

에이전트가 고르고 이유를 댑니다. **당신은 그 판단을 봅니다.**

올리려 하면 이렇게 막힐 수 있습니다.

```
Error: 승급 게이트를 넘지 못했습니다: 이어지는 위키링크가 0개로 min_wikilinks 2개에 못 미칩니다
위키에 있는 문서를 가리키는 링크를 2개 더 추가하세요. 없는 슬러그와 inbox 문서는 세지 않습니다
```

**거절 사유가 이것 하나뿐입니다.** 길이도 형식도 주제도 막지 않습니다.

왜 링크만 보냐면, 어디에도 안 이어진 문서는 반년 뒤에 찾아지지 않기 때문입니다. 잘 쓴 문서인지 도구는 모릅니다. 이어져 있는지는 압니다.

에이전트에게 링크를 채우게 하고 다시 올리게 하세요. **이을 곳이 없으면 그것이 신호입니다.** 아직 올릴 때가 아니거나, 먼저 올려야 할 다른 문서가 있습니다.

위키가 작을 때는 게이트가 유예됩니다.

```
경고: 링크 대상 문서가 1개로 min_wikilinks 2개보다 적어 게이트를 유예했습니다. 위키가 자라면 게이트가 다시 적용됩니다
```

## 5. 꺼내 씁니다

**에이전트에게**

```
지난달에 배포 롤백 얘기 뭐였지?
```

에이전트가 `search`로 어느 문서인지 찾고 `recall`로 내용을 꺼냅니다.

```
  1   6.84  context  배포-롤백-전사
  2   4.68  inbox    2026-08-22-회고-2026-04
  3   4.56  inbox    2026-08-22-슬랙-스레드
```

`search`는 **어디 있는지**만 냅니다. 내용은 안 냅니다.

```
1  6.00  [[배포-롤백-전사]]  context/배포-롤백-전사.md:16-85
```

`recall`이 **본문 조각**을 냅니다. 줄 번호까지 붙어서 어디서 왔는지 알 수 있습니다.

둘이 나뉜 이유가 있습니다. 검색은 짧고 싸야 하고, 회수는 인용할 만큼 길어야 합니다. 하나로 합치면 둘 다 어중간해집니다.

**낱말이 안 겹치면 의미로 찾습니다.**

```
engram search "장애 대응" --semantic
```

이건 `bridge`가 만들어 둔 벡터를 읽습니다. 한 번도 안 돌렸으면 벡터가 없다고 알려 줍니다.

## 6. 다시 만납니다

지식관리의 진짜 문제는 넣는 것이 아니라 **잊는 것**입니다.

**에이전트에게**

```
요즘 안 본 것 중에 다시 볼 만한 것 있어?
```

```
다시 꺼낼 문서 5개 (stale_days 30일, 기준 2026-11-22)
  - 배포-롤백-전사: 마지막 갱신 92일 전, 제시한 적 없음
  - 디스크-소진-슬랙: 마지막 갱신 92일 전, 제시한 적 없음
아무도 안 가리키는 문서 8개
  - 로그-검색-사용법
```

축이 셋입니다.

| 커맨드 | 무엇을 보나 |
|---|---|
| `resurface` | **시간.** 오래 안 본 것, 아무도 안 가리키는 것 |
| `bridge` | **관계.** 닮았는데 안 이어진 짝 |
| `digest` | **기간.** 그 사이에 무엇이 바뀌었나 |

`bridge`가 이 도구의 특별한 자리입니다. 낱말이 안 겹치는데 같은 문제를 다루는 문서 짝을 찾습니다. 사용자가 "화면이 한참 멈춰서 두 번 눌렀다"고 적은 것과 엔지니어가 "상위 백분위 응답이 320밀리초로 튀었다"고 적은 것이 같은 새벽의 같은 일입니다. 검색으로는 안 이어집니다.

## 7. 에이전트가 못 하는 것

도구 목록에 `promote`가 없습니다. 일부러 뺐습니다.

| 에이전트가 하는 것 | 사람이 하는 것 |
|---|---|
| `capture`로 `inbox`에 넣기 | **`context`로 올리기** |
| 검색, 회수, 백링크, 재발견 | **되돌리기, 폐기** |
| 링크 후보 제안 | 그 제안을 받을지 판단 |
| 규칙 조회 | 규칙 바꾸기 |

**에이전트가 쓸 수 있는 곳은 `inbox`까지입니다.**

승급은 "이것이 나중에도 쓸 지식이다"라고 선언하는 일입니다. 그 선언을 도구가 대신하면 위키가 쓰레기로 찹니다. 그리고 그것을 알아채는 데 몇 달이 걸립니다.

셸을 쥔 에이전트는 `engram promote`를 직접 칠 수 있습니다. 막을 방법이 없습니다. 그래서 **스킬 문서가 하지 말라고 적어 두었습니다.** 에이전트가 그것을 어기고 올리면 그 자리에서 되돌리게 하세요.

`engram lint`가 언제든 위키 상태를 봅니다. error가 0이어야 합니다.

```
검사한 파일 10개, error 0, warn 25, reject 1
```

warn은 괜찮습니다. error가 있으면 손으로 고친 자리가 있다는 뜻입니다.
