# 목록이 같은 값을 두 번 보여 주고 있었다

## 배경

핸즈온 5단계를 검수하다가 나왔다. `search`의 텍스트 출력이 이랬다.

```
  1  1.54  배포-설정-키-사건  archive/배포-설정-키-사건.md
  2  1.34  캐시-무효화-정리  context/캐시-무효화-정리.md
```

**슬러그와 경로가 같은 값이다.** 경로는 슬러그에 디렉토리와 `.md`를 붙인 것뿐이다. 네 칸 중 두 칸이 같은 것을 말한다.

경로에만 있는 정보는 **어느 단계에 있는가** 하나다. 그것이 사람이 목록에서 실제로 쓰는 정보다. `archive` 문서가 1위로 나왔을 때 폐기된 것임을 아는 근거가 그 디렉토리 이름이다.

같은 검수에서 `index.DocEntry.Title`이 **쓰이지 않는다**는 것도 드러났다. 색인을 만들 때 본문 첫 헤딩을 뽑아 필드에 넣고 JSON에 쓰는데, **읽는 코드가 없다.** `resurface`와 `serve`의 제목은 각자 문서를 다시 읽어 만든다.

## 판단 근거

**목록의 목적은 어느 문서를 열지 고르는 것이다.** 그 판단에 필요한 것은 무엇에 관한 문서인가와 어느 단계에 있는가다. 경로 전체는 후자를 담고 있지만 앞부분이 슬러그와 겹친다.

**단계만 떼어 내면 겹침이 사라진다.** 줄이 짧아지고 `archive`나 `inbox` 같은 단어가 슬러그 앞에 서므로 눈에 먼저 들어온다.

**`--json`에서는 경로를 뺄 수 없다.** 기계는 파일을 열어야 한다. 텍스트와 JSON의 대상이 다르므로 같은 필드를 낼 이유가 없다.

**제목은 텍스트에 안 낸다.** 슬러그가 제목에서 만들어지는 경우가 흔해 둘을 나란히 내면 같은 말이 두 번 나온다. 실제로 `캐시-무효화-정리`와 `캐시 무효화를 설계하는 네 가지 방법`이 한 줄에 함께 서면 줄만 길어진다.

**`--json`에는 담는다.** 슬러그가 `2026-08-17-test2`처럼 내용을 안 말할 때 제목이 유일한 단서다. 그리고 이미 색인에 있는 값이라 새로 계산할 것이 없다. **쓰이지 않던 필드가 이 결정으로 살아난다.** 안 살릴 것이면 지우는 것이 맞고, 지우기보다 쓰는 쪽이 낫다.

**반대 논거를 검토했다.** 텍스트에도 제목을 내면 슬러그가 불투명할 때 도움이 된다는 것이다.

기각한다. 슬러그가 불투명한 것은 슬러그를 성의 없이 지었다는 뜻이고, 그 신호를 목록이 가려 주면 고칠 이유가 사라진다. 위키링크가 슬러그로 걸리므로 **슬러그가 읽히게 짓는 것이 이 도구를 쓰는 사람의 일이다.**

## 결정

텍스트 출력을 순위, 점수, 단계, 슬러그 넷으로 바꾼다.

```
  1   1.54  archive  배포-설정-키-사건
  2   1.34  sources  2026-02-18-캐시-무효화를-설계하는-네-가지-방법
  3   1.34  context  캐시-무효화-정리
```

단계는 순회 경로의 첫 조각이다. 위키 루트에 있는 문서(`index.md`)는 `루트`로 낸다.

`--json`은 `path`를 유지하고 `title`을 더한다. `index.SearchResult`가 `Title`을 실어 나른다. CLI와 MCP의 `search`가 같은 구조를 낸다.

## 결과

- 목록 줄에서 겹치는 정보가 사라진다.
- 색인이 담고만 있던 `Title`이 `--json`으로 나간다.
- 회귀 시험을 더했다. 텍스트에 단계가 있고 `.md`가 없는지, `--json`에 경로와 제목이 있는지다.
- 골든 스냅샷과 MCP 도구 응답이 바뀐다.

## 열린 항목

- `recall`의 조각 머리줄은 아직 경로와 줄 범위를 낸다. 그쪽은 인용 출처라 경로가 필요하므로 이 결정의 대상이 아니다.
- 슬러그가 불투명할 때 목록만으로는 판단이 안 된다. 그때는 `--json`이나 `recall`을 쓴다. 텍스트 목록에 제목을 내는 문제는 요구가 반복되면 다시 본다.
