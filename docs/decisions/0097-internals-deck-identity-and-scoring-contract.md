# 내부 구조 덱의 정체를 읽기 문서로 확정하고 채점 계약을 둔다

## 맥락

`docs/course/internals.html`은 여러 번 재작업했는데 수렴하지 않았다. git 이력에는 생성 커밋과 하니스 커밋 둘뿐이고 나머지 수정은 전부 워킹트리에서 파일 전체를 갈아엎는 방식이었다. 유지할 것을 정하는 기준 없이 결과물만 반복 생성된 것이 원인이다.

결정 시점에 문서를 실측했다. 슬라이드 31장, SVG 도식 22개, 도식 하나의 글자 요소 평균 28.8개에 최대 50개다. 정량 주장이 43곳인데 그중 4곳이 이미 낡아 있었다(ADR 건수 표기 3곳, eject 하니스 픽스처 표기 1곳. 직전 커밋에서 교정). 문서는 [0096](0096-docs-harness-checks-quantitative-claims.md)이 만든 하니스의 검사 범위 밖이라 낡음을 기계가 잡지 못했다.

불만의 정체를 넷으로 가른다.

| 증상 | 실측 근거 |
|---|---|
| 밀도 과잉 | 도식 하나에 글자 서른 개는 발표 자료가 아니라 기술 문서를 도식으로 옮긴 것이다. 읽기 모드가 기본 시작이라는 설정이 그 자백이다 |
| 서열 부재 | 챕터 분량이 균등하고 중요도 서열이 없다. 전체성을 담으려다 교육 순서가 사라졌다 |
| 유지 비용 | 정량 주장 43곳 중 4곳이 낡았고 산문 카운트는 하니스 검사 대상이 아니었다 |
| 청중 불명 | 스스로 정규 세션 밖 심화 자료라 밝히면서 선행 자료와의 관계가 문서 안에 안내되지 않는다 |

유지할 강점도 실측되었다. 수치가 ADR 실측에 묶이고, 챕터마다 구조의 이유를 원인 하나로 환원하는 설명 문법이 일관되고, 근거가 덧붙임으로 분리되어 있다.

## 결정

### 정체는 읽기 문서이고 파일은 하나다

이 자산은 읽기 문서다. 읽기 모드 기본 시작은 실수가 아니라 실제 쓰임이었다. 정체를 확정하면 밀도 기준이 "슬라이드처럼 줄여라"가 아니라 "재료를 제 형식에 담아라"가 된다. 표는 표로, 코드는 코드 블록으로, 도식은 명제 하나짜리 그림으로 담는다. 슬라이드 모드는 지우지 않되 본문만 순회하는 부산물로 남긴다.

덱과 참조 자료를 파일 둘로 나누는 안은 기각한다. 이번 재작업의 병인이 유지 비용인데 정량 주장이 두 벌이 되면 병인이 커진다.

### 서열의 잣대는 세 원칙이다

정리 장의 세 원칙(결정론이 존재 조건, 판정은 한 벌, 비용은 자리를 옮긴다)을 본문과 덧붙임을 가르는 잣대로 승격한다. 원칙 중 하나를 증명하는 슬라이드는 본문이고, 사실만 알려주는 슬라이드는 덧붙임이다. 덧붙임은 각 장 끝에 접고 슬라이드 모드에서는 건너뛴다. 덧붙임도 아래 수치 계약과 검사 범위에 똑같이 포함된다. 본문만 갱신되고 덧붙임에서 낡음이 자라는 것을 막기 위해서다.

### 밀도 규칙 다섯

1. 도식 하나는 명제 하나만 주장한다. 둘이면 도식을 나눈다.
2. 대응, 목록, 열거는 SVG로 그리지 않는다. HTML 표로 담는다.
3. 도식의 글자 요소는 18개 이하로 한다. 문장형 라벨은 본문으로 승격하고 도식에는 명사구만 남긴다.
4. 본문에는 도식이 증명하는 문장을 올린다.
5. 같은 서술을 본문, 도식 라벨, 덧붙임 중 두 곳 이상에 두지 않는다. 덧붙임에는 ADR 번호, 측정 조건, 예외만 둔다.

### 수치는 세 종류로 갈라 취급한다

| 종류 | 예 | 규칙 |
|---|---|---|
| 카운트 | ADR 건수, 규칙 종수, 커맨드 수 | 본문 전체 1회만 적는다. 그 외 자리는 정성 표현으로 쓴다 |
| 실측 성능 | 문서당 인코딩 시간, 유사도 하한 | 측정 조건과 ADR 번호를 같은 줄에 둔다. 조건이 붙으면 시간이 지나도 거짓이 되지 않는 고정 인용이 된다 |
| 구조 상수 | 모듈 수, 승급 단계 수, 벡터 차원 | 제한 없이 쓰되 덧붙임에 코드 위치를 병기한다 |

단일 변경이 문서를 고치게 만드는 수정 반경은 2장 이하로 한다. 이 ADR 자체가 첫 사례다. 이 문서가 생기면서 ADR 건수가 하나 늘고, 같은 커밋에서 덱의 카운트 표기를 갱신한다. 카운트가 본문에 세 곳 있는 지금 구조가 이 계약 위반이며, 리라이트에서 1회로 줄인다.

### 채점 기준 여섯

리라이트와 이후 재작업은 이 여섯으로 판정한다. 기준을 상속하면 재작업은 논쟁이 아니라 채점이 된다.

| # | 기준 | 통과선 |
|---|---|---|
| C1 | 진입 계약. 청중, 선행 자료와의 관계, 읽고 나면 판단할 수 있는 것이 문서 안에 문장으로 있다 | 초반 1장 안에 존재 |
| C2 | 질문 사슬. 각 장의 첫 질문이 바로 앞 장에서 발생한다 | 끊기는 지점 1개 이하 |
| C3 | 원칙 귀속. 모든 본문 슬라이드가 세 원칙 중 하나를 증명한다 | 비귀속 본문 슬라이드 0 |
| C4 | 도식 예산. 밀도 규칙 다섯을 지킨다 | 초과 도식 0 |
| C5 | 세 층 배타성. 본문, 도식 라벨, 덧붙임의 중복 서술이 없다 | 중복 서술 0쌍 |
| C6 | 수치 결속. 모든 정량 주장이 하니스 대조 대상이거나 ADR 번호와 측정 조건을 동반한다 | 무결속 숫자 0 |

C4나 C6 미달은 구조 리라이트 사유이고, C1부터 C3까지의 미달은 재배치로 회복한다.

### 작업 방식

장 단위로 커밋하고 커밋 메시지에 통과시킨 기준을 적는다. 파일 전체 교체는 이번 늪의 원인이었던 방식이므로 금지한다. 시범 장 하나를 먼저 고쳐 기준이 실제로 읽히는지 확인한 뒤 나머지로 확장한다.

## 결과

낡은 주장 4곳은 직전 커밋에서 교정되었다. 하니스의 검사 범위를 course 산문까지 넓히는 일은 이 ADR의 결정이 아니라 후속 작업이다. [0096](0096-docs-harness-checks-quantitative-claims.md)의 대조 방식을 상속하되, 코드 블록과 표와 도식 라벨을 제외한 산문만 보게 하는 마킹 방식은 그 작업에서 정한다.
