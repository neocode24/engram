# 출력 언어는 사용자 환경이 정하고 카탈로그는 바이너리에 묶는다

## 배경

커맨드 출력과 에러 메시지가 한국어 전용이다. 문자열은 860개이며 `internal/cli`에 553개가 몰려 있다.

한편 `README.md`는 영어를 기본으로 두고 한국어를 `docs/ko-KR/README.md`로 분리해 두었다. 저장소 공개를 전제로 한 결정이다. 그래서 영어권 사용자가 영어 문서를 읽고 설치한 뒤 첫 실행에서 한국어를 받는 상태가 되어 있다. 문서와 바이너리가 어긋나 있다.

## 판단 근거

**언어 설정을 `engram.yaml`에 두면 안 된다.** 그 파일은 위키 설정이며 git으로 커밋되어 팀이 공유한다([0017](0017-yaml-for-config-and-frontmatter.md)). 스키마 속성과 임계값처럼 **위키의 성질**을 담는 자리다. 출력 언어는 위키의 성질이 아니라 그것을 읽는 사람의 성질이다. 한국어 사용자와 영어 사용자가 같은 위키를 공유하면 어느 쪽 언어를 커밋해야 하는지 답이 없다.

**외부 i18n 라이브러리를 쓰지 않는다.** 필요한 것은 ID로 문자열을 찾고 `fmt`로 채우는 것뿐이다. 복수형 규칙도 성별 변화도 쓰지 않는다. 한국어에 복수형이 없고 영어 쪽은 문장을 그렇게 쓰지 않으면 된다. 어순 차이는 `fmt`의 인자 색인(`%[1]s`)이 이미 푼다. 표준 라이브러리로 충분한 자리에 의존성을 늘리지 않는다.

**기본값을 영어로 두면 이 저장소의 산출물이 한꺼번에 어긋난다.** 골든 스냅샷, `README.md`에 실은 실행 결과, 강의 자료와 실습 진행서에 실은 출력이 전부 한국어다. 기본을 뒤집으면 그것들을 같은 커밋에서 다시 찍어야 하고, 영어 문서가 아직 없으므로 얻는 것도 없다.

**`LANG` 환경변수를 보지 않는다.** 표준 관행이지만 여기서는 해롭다. 한국어 사용자의 macOS `LANG`이 흔히 `en_US.UTF-8`이다. 그것을 근거로 언어를 고르면 강의 수강생 다수가 문서와 다른 출력을 받는다. 언어는 명시적으로만 바뀐다.

**검증 계약은 언어가 늘어도 두 배가 되지 않는다.** 두 계약이 걸려 있다. 골든 스냅샷의 바이트 비교와, `eject`가 내보낸 Python 린터가 `engram lint`와 같은 판정과 메시지를 내야 한다는 동등성이다. 둘 다 **한 번에 한 언어**로만 성립하면 된다. 시험이 언어를 고정하면 지금 파일이 그대로 유효하다. 다른 언어는 바이트 비교 대신 **카탈로그 완결성**으로 지킨다. 모든 ID가 두 언어에 다 있고 서식 지정자가 같은지 보는 시험이다.

**빠진 메시지는 ID를 그대로 낸다.** 빈 문자열을 내면 출력에서 문장이 통째로 사라져 원인을 찾기 어렵다. `lint.gate.min_wikilinks` 같은 ID가 화면에 보이면 어느 메시지가 빠졌는지 즉시 드러난다.

## 결정

### 언어 결정

우선순위는 셋이다.

| 순위 | 출처 |
|---|---|
| 1 | `--lang` 전역 플래그 |
| 2 | `ENGRAM_LANG` 환경변수 |
| 3 | `ko` |

허용값은 `ko`와 `en`이다. 그 밖의 값은 에러이며 허용값을 함께 낸다. 조용히 무시하면 오타를 낸 사용자가 왜 언어가 안 바뀌는지 알 수 없다.

언어는 `PersistentPreRunE`에서 **가장 먼저** 정한다. 그 뒤의 에러부터 선택한 언어로 나온다.

### 카탈로그

`internal/i18n`이 카탈로그를 담고 컴파일 시점에 바이너리에 묶인다. 외부 파일을 읽지 않는다. 단일 바이너리 배포([0007](0007-platform-and-distribution.md))가 깨지지 않아야 한다.

**카탈로그는 영역별 파일로 나눈다.** `internal/i18n/catalog_<영역>.go`가 `init`에서 `Register`를 부른다. 한 파일에 몰면 여러 사람이 동시에 손댈 때 반드시 충돌한다.

메시지 ID는 `<영역>.<맥락>.<이름>`이다. 소문자와 밑줄만 쓴다. 예: `cli.promote.gate_reject`, `lint.gate.min_wikilinks`, `doctor.env.git.ok`.

같은 ID를 두 번 등록하면 프로그램을 멈춘다. 조용히 덮으면 어느 쪽이 이겼는지 알 수 없고 출력이 파일 순서에 따라 달라진다.

어순이 다른 문장은 인자 색인을 쓴다. `"%[2]s의 %[1]s"` 형태다.

### 검증

| 무엇 | 어떻게 |
|---|---|
| 골든 스냅샷, 여정, eject 동등성 | 시험이 `ENGRAM_LANG=ko`를 못 박는다. 기존 파일이 그대로 유효하다 |
| 다른 언어 | 카탈로그 완결성 시험. ID 집합이 같고 서식 지정자가 같은지 본다 |

### 번역하지 않는 것

로그가 아니라 데이터인 문자열은 카탈로그에 넣지 않는다. 프론트매터 키와 값, 슬러그, lint 규칙 ID(`gate.min-wikilinks`), 설정 키, JSON 필드 이름이다. `--json` 출력의 **키**는 언어와 무관하고, 그 안에 담기는 사람용 문장만 카탈로그를 거친다.

`eject`가 내보내는 산출물은 **내보내는 시점의 언어로 굳는다.** 그 파일들은 사용자 저장소로 넘어가 engram과 무관하게 사는 것이므로, 나중에 언어를 바꿔도 따라가지 않는다.

## 결과

- `engram --lang en`과 `ENGRAM_LANG=en`이 동작한다. 기본은 한국어이므로 기존 문서와 스냅샷이 그대로 유효하다.
- `internal/i18n` 패키지가 생긴다. 의존성은 늘지 않는다.
- `README.md`에 출력 언어를 바꾸는 방법을 적는다.

## 열린 항목

- 기본값을 `en`으로 뒤집는 시점. 영어 문서와 영어 골든이 갖춰진 뒤다. 그때 `LANG` 환경변수를 볼지도 함께 정한다.
- 세 번째 언어가 필요해지면 카탈로그 완결성 시험이 그대로 늘어나는지. 지금 구조는 언어 수에 선형이다.
