# 날짜 필드는 그 값을 읽는 단계에만 쓴다

## 배경

`sync`가 날짜 필드를 단계 구분 없이 넓게 쓰고 있었다. `sourced_at`은 모든 문서에 들어갔고 `context` 문서도 받았다. `updated`는 `sources`만 빼고 `inbox`와 `archive`에도 들어갔다. upstream은 둘 다 대상을 한정한다. `scripts/sync_updated_field.py:29-30`은 `updated` 갱신 대상을 `context`로, `scripts/backfill_source_dates.py:30`은 `created`와 `sourced_at` 백필 대상을 `sources` 아래로 한정한다.

그 밖에 `created`의 재료가 하나 비어 있었다. upstream `scripts/backfill_source_dates.py:32-34, 74-81`은 `created` 재료로 파일명 날짜 접두사를 쓴다. `YYYY-MM-DD-slug`와 `YYYY-MM-slug` 둘 다 받는데, 연월까지만 아는 자료가 54개 있기 때문이다. engram은 `created` 형식으로 연월 정밀도를 허용하면서(`internal/config/config.go`의 날짜 레이아웃) 파일명에서 날짜를 뽑는 코드가 없었다. 도구가 만든 파일은 이름에 날짜를 받으므로 문제가 없다. 밖에서 만들어 `inbox/`에 떨어뜨린 파일과 다른 위키에서 마이그레이션한 문서에서 필요하다.

## 가르는 기준

**그 값을 읽는 쪽이 있는가다.** `updated`는 재발견의 노후 판정 입력이고(ADR 0066) 재발견 대상은 `context`뿐이다. `sourced_at`은 원본을 입수한 시각이라 `sources`의 것이다. 파생 문서는 원본을 `derived_from`으로 가리키고 그 원본이 자기 `sourced_at`을 갖는다. 아무도 읽지 않는 값을 채우면 사용자가 그 값에 뜻이 있다고 믿는다. 빈 값은 "모른다"가 되고 채워진 값은 "안다"가 되는데 아무도 읽지 않는 필드의 값은 그 믿음에 보증이 없다.

## 판단

- `updated`는 `context` 단계 문서에만 쓴다. 재료는 git 마지막 커밋 날짜다.
- `sourced_at`은 `sources` 단계 문서에만 쓴다. 재료는 git 최초 커밋 날짜다.
- `created`는 단계를 가리지 않되 비어 있을 때만 채운다. 재료의 순서는 아래와 같다.

| 순서 | 재료 |
|---|---|
| 1 | git 최초 커밋 날짜 |
| 2 | 파일명 접두사 |
| 3 | 채우지 않는다 |

파일명 접두사는 `YYYY-MM-DD-`와 `YYYY-MM-` 둘을 받고 그 뒤에 슬러그가 이어져야 한다. 날짜만 있는 파일명은 받지 않는다.

`update` 커맨드의 `updated` 자동 기입은 이 결정의 대상이 아니다(ADR 0032). 그쪽은 사람이 문서를 고친 사실을 그 자리에서 남기는 것이고 `sync`는 git 이력으로 나중에 정정하는 것이다. 성격이 다르므로 `sync`만 좁힌다.

이미 있는 값을 지우지 않는다. 안 쓰는 것과 지우는 것은 다르다. 지우는 것은 `migrate`의 성격이다(ADR 0038). `sync`는 정정 커맨드이지 청소 커맨드가 아니다.

## 파일명을 보조 재료로 둔 근거

git 이력을 우선하고 파일명은 이력이 없을 때의 대체재로만 쓴다. 두 값이 다를 때 어느 쪽이 옳은지 정할 근거가 없고, ADR 0037이 `sync`의 판정 근거를 git 이력으로 정했기 때문이다. 판정 근거가 하나여야 같은 입력에 같은 출력이 나온다.

반대 논거를 검토했다. 파일명은 사람이 지은 것이라 git 커밋 시각보다 사실에 가까울 수 있다. 회의 날짜로 파일명을 짓고 며칠 뒤에 커밋하는 일이 흔하다. 이 논거는 옳지만 이번에는 기각한다. `sync`는 정정 커맨드라 판정 근거를 하나로 두어야 결과가 예측 가능하고, 사람이 아는 날짜는 `--created`로 직접 줄 수 있는 경로가 이미 있기 때문이다. 도구가 두 재료를 저울질하면 어느 쪽을 믿었는지 출력을 일일이 확인해야 한다. 그 판단은 사람에게 남겨 두고 도구는 이력 하나만 본다.

## 결과

- `sync` 출력이 재료별로 갈린다. git 이력에서 온 것과 파일명 접두사에서 온 것을 건수를 나눠 알리므로 사용자가 근거를 안다.
- 커밋되지 않은 파일 중 파일명에 재료가 있는 것은 `created`를 받는다. 재료가 없는 것은 여전히 건너뛰고 개수를 알린다.
- 날짜만 있는 파일명과 이력도 접두사도 없는 문서는 채우지 않는다.
