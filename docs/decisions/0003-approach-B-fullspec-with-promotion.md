# 0003 접근법 B: 풀스펙 + 승급 파이프라인

## 결정

v1을 **풀스펙(하이브리드 검색·재발견 루프·웹 UI·에이전트 skill 내장) + llm-wiki의 승급 파이프라인(inbox→sources→context)**으로 구현한다.

## 검토 후보

| 접근 | 내용 | 기각 근거 |
|---|---|---|
| A. 교육 역산 | 수강생 결과물을 역산한 최소 도구만 | 본인이 B를 선호. 홍보성/완성도 부족 |
| **B. 풀스펙 + 승급** | **채택** | — |
| C. 승급 게이트 단일 도구 | 승급 파이프라인만 | 교육 한 사이클(검색/회수)이 불완결 |

## B 선택 근거

A가 "교육에 필요한 만큼만"으로 비용/일정이 안전하다는 추천이었으나, 본인 판단은 홍보성·완성도 우선:

- 홍보 산출물로 풀스펙 수준의 완성도가 필요하다.
- "다른 PKM은 승급 게이트가 없고 우리는 코드가 강제한다"는 차별화가 풀스펙 위에서 더 선명하다.

## 비용 수용

- 본인이 실사용하지 않을 도구에 최대 작업량을 투입한다는 비용 효율 우려를 수용한다.
- 마일스톤을 나누어 단계적 출하로 일정 리스크를 관리한다.

## 차별점: 승급 파이프라인

풀스펙의 각 요소(검색·재발견·웹 UI·skill)는 보편적인 PKM 기능이다. 이 프로젝트의 유일한 diff는 **inbox→sources→context 승급을 코드가 강제**한다는 점이다.
