# 할 일 원장은 문서를 넣는 명령에서 선언받고 loopback 화면에서만 쓴다

## 맥락

upstream은 지식 계층(`inbox`, `sources`, `context`) 옆에 할 일 원장 `pin/`을 운영한다. 위키 문서에서 나온 할 일을 모아 상태를 관리하고, 원장을 고치는 곳은 적용 스크립트 하나뿐이다. [0104](0104-upstream-pin-rules-are-held-out-of-the-harness.md)는 그 규칙을 harness가 따라가지 않기로 했다. 따라갈 대상이 engram에 없었기 때문이다.

이 결정은 그 대상을 만든다. 범위는 위키 출처 하나로 좁힌다. engram은 개인용이고 로컬에서만 쓴다. 미리알림, 채팅 채널, 캘린더는 upstream의 운영 자동화에 속하며 [0102](0102-engram-stays-in-maintenance-and-adapts-to-the-learner-toolchain.md)가 옮기지 않기로 한 것이다.

설계의 근거와 실측은 설계 문서에 있고 이 문서는 결정만 적는다. 구현은 `internal/pin`, 비교 시험은 `harness/pin`이다.

## 결정

- engram에 할 일 원장을 둔다. 이름은 upstream과 같이 `pin`이다. 출처는 위키 문서 하나다.
- 원장은 켜야 켜진다. `engram pin init`이 위키 루트에 `pin/`을 만든다. `pin/config.json`이 없는 위키에서 기존 커맨드의 동작과 출력은 바뀌지 않는다.
- 원장을 켠 위키에서 `capture`, `source`, `promote --to sources`는 `--pin` 선언을 받는다. 선언이 없으면 쓰지 않는다. 선언의 요청이 하나라도 게이트에서 거절되면 문서도 쓰지 않는다. 할 일이 없다는 판단은 `--pin none`이며 `pin/log`에 남는다.
- 할 일인지의 판단은 명령을 부른 에이전트가 한다. 바이너리는 선언을 했다는 사실과 선언의 형식만 강제한다.
- 근거의 경로, 단계, 날짜는 명령이 채운다. 근거는 그 명령이 쓰는 문서뿐이다. 선언이 이 값을 직접 적으면 거절한다.
- 선언이 낼 수 있는 연산은 `add`, `update_ai`, `set_owner`, `set_work`, `set_due`, `add_relation`, `propose` 일곱이다. 같은 일곱을 upstream의 `extract` 경로가 허용한다. `move_path`는 선언이 아니라 문서를 옮기는 명령이 낸다. 선언으로 들어온 새 일은 제안 표시가 붙는다. 확정은 사람이 화면에서 한다. 선언으로는 상태를 바꾸거나 지울 수 없다.
- 원장을 쓰는 곳은 `internal/pin`의 게이트 하나다. CLI(`pin apply`와 `--pin`), MCP, 화면이 같은 것을 부른다. 하나의 요청을 적용한 뒤 원장 전체를 검사하고, 어긋나면 그 요청만 되돌린다.
- 원장의 파일 형식과 세 요청 경로(`web`, `command`, `extract`)의 허용 연산 표는 upstream과 같게 둔다. 같은 입력에 원장 파일이 바이트 단위로 같은지를 `harness/pin`이 upstream 파이썬으로 견준다.
- 문서를 옮기는 커맨드(`promote`, `mv`, `demote`, `archive`)는 그 문서를 근거로 둔 항목의 경로를 같은 명령에서 고친다. 인용문은 다시 대조하지 않는다. 원장이 참조하지 않는 문서의 이동은 요청도 로그도 만들지 않는다.
- 옮겨진 문서를 근거로 둔 열린 일이 있으면 출력에 번호와 제목을 적는다. 닫을지는 사람이 화면에서 정한다. context 승급을 일의 완료 신호로 읽지 않는다. context 문서는 판단 대상이 아니라서 `promote`(context)는 `--pin`을 받지 않는다.
- 화면은 upstream의 화면 파일을 바이너리에 넣어 쓴다. 다시 짜지 않는다. 설정 구역만 바꾼다(`API='/pin/api/'`, `SOURCES=['wiki']`, `AUTH='none'`). 사이트 구역은 지운다.
- engram은 원장을 커밋하지 않는다. 쓰기 잠금은 `pin/.lock`이며 30초가 지난 잠금은 버린다.

## upstream과 일부러 달리하는 점

기록은 `docs/spec-map.md`의 Pin 절에 표로 둔다. 요약은 다음과 같다.

| 항목 | upstream | engram |
|---|---|---|
| 프로젝트 | 1개 이상 | 0개 허용(새 위키) |
| 화면 표현의 금지어 검사 | 있음 | 없음 |
| 상태의 URL 제거 | 있음 | 없음 |
| 문서 링크 | 모든 단계 | context 문서만 |
| 미리알림, 캘린더, 질문 생성 | 있음 | 없음 |
| 상위 해제 문장 | 파이썬 `str(None)`이 새는 표현 | "상위 없음" |
| 시각 형식 | `Z` 없이 `+09:00` | 같음 |

시각 형식은 upstream이 시스템 파이썬 3.9가 `Z`를 읽지 못하는 점 때문에 고른 것을 그대로 따른다.

## 기각한 대안

- **판단을 `promote`까지 넓힌다.** `promote`는 게이트 명령이라 거절 사유를 늘리지 않는 것이 이 저장소의 원칙이다. context 승급이 일의 완료를 뜻하지도 않는다. 완료는 그 뒤의 문서에 적히고, 그 문서는 inbox나 sources로 들어오며 선언의 `propose`가 읽는다.
- **바이너리가 문서에서 할 일을 추출한다.** [0014](0014-llm-boundary-agent-drives-binary.md)가 막는다. LLM 호출은 에이전트 몫이다.
- **화면을 Go 템플릿으로 다시 짠다.** upstream 화면은 인라인 스크립트 하나에 상태 처리가 들어 있고 시험 항목이 많다. 다시 짜면 두 구현이 갈라진다.
- **상태 파일을 두고 서버가 갱신한다.** 읽을 때마다 원장에서 만든다. 원장과 상태가 어긋나는 경우를 없앤다.
- **`--pin`을 모든 위키에서 필수로 한다.** 켜지 않은 위키의 동작이 바뀐다. 교재의 실습 위키가 영향을 받는다.

## 결과

- 최상위 커맨드가 서른이 된다.
- 화면 파일의 다른 출처 코드가 죽은 코드로 실린다. 화면 파일은 upstream과 바이트 차이를 최소로 두려고 지우지 않는다.
- 에이전트가 `pin apply`로 제 제안을 수락하는 것을 코드로 막지 못한다. 스킬 문서가 사람이 시킨 변경만 하라고 적을 뿐이다. 선언 경로(`--pin`)는 수락과 상태 변경을 받지 않으므로 이 구멍은 `pin apply`에만 있다.
- 쓰기 경로가 `serve`에 생긴다. [0044](0044-serve-is-read-only-and-shows-only-vetted-knowledge.md) 개정 참조. 쓰는 곳은 `pin/`뿐이고 리스너가 loopback일 때만 성립한다.
- 요청 헤더 검사(Host, Origin, `X-Pin`, `Content-Type`)는 DNS rebinding과 다른 사이트의 요청을 막는다. 역방향 프록시나 터널이 Host를 고쳐 loopback으로 넘기면 이 검사를 통과한다. 원격 접속은 지원하지 않는다.
- upstream이 빠르게 바뀌는 동안 주간 harness가 대부분 PR 경로로 간다.

## 상세

### 0044에 두는 예외

- 0044의 "쓰기 경로를 두지 않는다"에 예외 하나를 둔다. `POST /pin/api/changes`다. 쓰는 곳은 `pin/`뿐이고 지식 계층은 화면에서 쓰지 못한다.
- 0044의 "기본 제외: `inbox/`, `sources/`"에 예외 하나를 둔다. Pin 화면은 항목의 근거로 인용된 inbox와 sources 문서의 제목, 경로, 절 이름, 인용문을 보인다. 문서 전문은 보이지 않는다.
- 두 예외는 리스너가 loopback 주소일 때만 성립한다. 그 밖의 주소에 묶이면 Pin 경로를 등록하지 않는다. "네트워크 표면에 쓰기를 두지 않는다"는 0044의 근거는 그대로 선다.
- `/pin`에 한해 인라인 스크립트를 해시로 허용하는 보안 정책을 따로 건다. 나머지 경로는 스크립트를 쓰지 않는다.
- loopback 판정은 `internal/expose`에 둔다. 노출 판정이 한 곳이라는 [0046](0046-pack-exports-files-and-anonymizes-by-user-dictionary.md)을 지킨다.

### 0102에 두는 예외

- "커맨드 범위는 1.0 그대로 닫아 둔다"에 예외 하나를 둔다. 할 일 원장(`pin`)이다.
- 0102가 기각한 "`serve`에 승인 버튼을 다는 컨셉 변경"은 그대로 기각이다. Pin 화면은 승급을 승인하지 않는다. 승급 승인은 0057대로 대화 안에서 문서 내용에 붙는다.
- 1.1 트랙을 열지 않는다는 결정과 llm-wiki의 운영 자동화(스케줄, 동기화 서비스)를 옮기지 않는다는 결정은 그대로다. 원장은 스케줄 없이 명령이 불릴 때만 쓰인다.
- 교재는 바꾸지 않는다. 원장은 켜야 켜지므로 실습 위키에 나타나지 않는다.

### 0057에 두는 변경

"`source`는 사람이 직접 친다"를 "출처와 작성일을 보여 주고 승인받은 뒤 에이전트가 실행한다"로 바꾼다. `source`에 `--pin` 선언이 붙으면 에이전트가 문서를 읽고 판단한 뒤 명령을 불러야 하므로 사람이 타이핑하는 명령으로 둘 수 없다. 사실 확인이 사람 몫이라는 근거는 그대로이고 타이핑만 넘어간다. `mv`, `demote`, `archive`는 그대로 사람이 친다.

### 0043에 두는 변경

MCP `capture`가 `pin` 인자를 받는다. 쓰기 도구는 여전히 하나이고 `promote`와 `source`는 여전히 내보내지 않는다. 도구 호출 사이에 사람이 없다는 0043의 걱정은 새 일이 제안으로만 들어가는 것으로 받는다. 이 항목을 떼면 MCP로 들어온 문서가 판단을 거치지 않는 구멍이 남는다.
