# 슬러그와 파일명 규칙

## 배경

`capture`, `source`, `promote`, `new` 넷이 전부 파일을 만든다. 어떤 이름으로 만들지가 정해져 있지 않다. 파일명은 위키링크의 슬러그와 같아야 하므로, 이름 규칙이 흔들리면 링크 무결성이 처음부터 깨진다.

설계 문서에는 규칙이 없다. upstream `llm-wiki`의 실제 파일명이 유일한 근거다.

## 판단 근거

**upstream 실물이 두 규칙을 쓴다.** `context/` 아래는 `a2a-agent-protocol.md`처럼 날짜 없는 영문 kebab-case이고, `inbox/`와 `sources/` 아래는 `2026-08-12-omniroute-llm-gateway-조사.md`처럼 날짜 접두사가 붙는다. 날짜 접두사는 장식이 아니다. upstream의 백필 스크립트가 `created` 값을 파일명 날짜에서 가져오므로 접두사가 데이터다.

**연월까지만 아는 자료가 실재한다.** upstream `sources/`에 `2025-06-...`, `2024-01-...` 형태가 있다. ADR 0009가 `created`에 `YYYY-MM`을 허용한 것과 같은 사실의 다른 표현이므로 파일명도 같은 정밀도를 받아야 한다.

**한글을 음차하지 않는다.** upstream 파일명에 한글이 섞여 있다. 이것을 로마자로 바꾸려면 음차 규칙이 필요한데, 이 바이너리에는 LLM이 없다(ADR 0014). 기계적 음차는 `전환방법론`을 `jeonhwanbangbeoblon` 같은 것으로 만든다. 아무도 그 슬러그로 링크하지 않는다. 원문을 보존하는 편이 사용자가 실제로 타이핑할 수 있는 결과를 낸다.

**슬러그를 소문자로 강제한다.** macOS와 Windows의 기본 파일시스템은 대소문자를 구분하지 않고 Linux는 구분한다. 대소문자만 다른 두 슬러그가 존재하면 git이 한쪽에서 충돌한다. 소문자 강제는 이 사고를 원천에서 없앤다. `doctor`가 파일시스템 대소문자 구분 여부를 점검하는 것도 같은 이유다.

## 결정

### 슬러그

제목에서 기계적으로 파생한다.

1. 소문자로 내린다
2. 공백과 구분자를 하이픈 하나로 바꾼다
3. 연속 하이픈을 하나로 줄이고 앞뒤 하이픈을 없앤다
4. 파일시스템에서 문제가 되는 문자와 Windows 예약 파일명을 제거한다
5. 한글은 보존한다. 음차하지 않는다

결과가 빈 문자열이면 에러이며, 호출자가 슬러그를 직접 지정하도록 안내한다. 사용자는 언제든 슬러그를 명시해 파생을 덮어쓸 수 있다.

### 파일명

| 도착지 | 형식 | 예 |
|---|---|---|
| `context/` | `<슬러그>.md` | `ai-gateway-pattern.md` |
| `inbox/`, `sources/` | `<YYYY-MM-DD>-<슬러그>.md` | `2026-08-12-llm-gateway-조사.md` |
| `inbox/`, `sources/` (연월만 아는 경우) | `<YYYY-MM>-<슬러그>.md` | `2025-06-cicd-pipeline-summary.md` |

날짜는 호출자가 준다. 파일을 만드는 계층이 시계를 읽지 않는다. `--now`로 고정한 실행이 같은 결과를 내야 하기 때문이다.

기존 파일은 덮어쓰지 않는다. 같은 이름이 이미 있으면 에러이며 기존 경로를 메시지에 담는다.

## 결과

- `internal/wiki`가 이 규칙의 단일 구현 지점이 된다. 네 커맨드가 같은 함수를 부른다.
- upstream 파일명이 그대로 engram의 입력이 된다. ADR 0005의 parity 비교에서 파일명 차이로 인한 잡음이 없다.

## 열린 항목

- 한글 슬러그가 URL이 되는 경우(`serve` 웹 UI)의 인코딩. 1.0 범위이며 그때 다룬다.
