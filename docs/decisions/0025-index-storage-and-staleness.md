# 인덱스 저장 형식과 신선도 정책

## 배경

ADR 0010이 한국어 검색을 문자 bigram과 직접 구현한 BM25로 정하고, 캐시를 위키 루트의 `.engram/`에 두기로 했다. 정하지 않은 것이 둘 남았다. 인덱스를 어떤 형식으로 저장할지와, 인덱스가 원문보다 낡았을 때 누가 언제 갱신할지다.

두 번째가 더 중요하다. `search`가 낡은 인덱스를 쓰면 사용자는 방금 쓴 문서를 못 찾는다. 그렇다고 `search`가 인덱스를 갱신하면 조회 커맨드가 파일을 쓰게 된다.

## 판단 근거

### 저장 형식

**규모가 형식을 정한다.** ADR 0010은 재검토 조건을 문서 2000개 또는 인덱스가 원문의 5배로 못 박았고, 현재 upstream이 358개다. 이 규모에서 JSON 파싱은 병목이 아니다.

**사람이 열어 볼 수 있어야 한다.** 검색 순위가 이상할 때 원인을 찾는 방법은 인덱스를 직접 보는 것이다. gob은 Go 프로그램 없이는 읽을 수 없고, SQLite는 도구가 필요하다. 순위를 소유하기로 한 이상 그 재료도 읽을 수 있어야 한다.

**SQLite는 의존성 문제가 따라온다.** cgo 바인딩은 ADR 0007의 `CGO_ENABLED=0` 제약과 충돌하고, 순수 Go 구현은 바이너리를 크게 만든다. 키워드 검색 하나를 위해 지불할 비용이 아니다.

### 신선도

**조회 커맨드가 파일을 쓰면 안 된다.** 읽기 권한만 있는 위키, 읽기 전용 마운트, 동시에 여러 세션이 도는 상황에서 전부 문제가 된다. 더 근본적으로 `search`는 조회다. 조회가 부작용을 갖기 시작하면 어디까지 쓰는지 사용자가 알 수 없다.

**그렇다고 침묵하면 안 된다.** 낡은 인덱스로 조용히 검색하면 사용자는 결과가 왜 이상한지 모른다. 도구가 아는 사실을 숨기는 것이므로, 알리되 막지는 않는다.

**mtime과 크기로 충분하다.** 내용 해시가 정확하지만 매 조회마다 전체 파일을 읽어야 한다. mtime은 git clone 시 갱신되어 거짓 양성을 낼 수 있는데, 그 결과는 "낡았다고 잘못 알리는 것"이라 안전한 방향의 오류다. 거짓 음성(바뀌었는데 안 바뀌었다고 판정)이 위험한데 mtime과 크기를 함께 보면 그 확률이 낮다.

**반대 논거를 검토했다.** 자동 갱신이 사용자 경험은 좋다. `search` 한 번으로 항상 최신 결과가 나온다. 그러나 그 편의는 `reindex`라는 커맨드의 존재 이유를 없앤다. 커맨드를 두고 자동으로도 하면 언제 무엇이 도는지 설명할 수 없다. 편의는 경고 메시지에 실행할 명령을 함께 실어 주는 것으로 대신한다.

## 결정

### 저장

| 항목 | 값 |
|---|---|
| 형식 | JSON |
| 위치 | 위키 루트 `.engram/index.json` |
| git | gitignore 대상 |

저장 내용은 스키마 버전, 문서별 항목(경로, 슬러그, 토큰 빈도, 문서 길이, 크기, 수정 시각), 전역 통계(문서 수, 평균 길이, 토큰별 문서 빈도)다.

**같은 위키를 두 번 색인하면 바이트까지 같아야 한다.** 맵 순회 순서가 흔들리므로 키를 정렬해 쓴다. 동점 문서의 순위는 슬러그 순으로 고정한다. 이것이 깨지면 ADR 0005의 검색 순위 parity 비교가 성립하지 않는다.

스키마 버전이 다르거나 JSON 파싱에 실패하면 인덱스를 무시하고 낡은 것으로 취급한다. 에러로 종료하지 않는다. 캐시가 깨졌다고 도구가 멈추면 안 된다.

### 신선도

- `reindex`가 인덱스를 만드는 **유일한** 커맨드다.
- `search`를 비롯한 조회 커맨드는 인덱스를 **읽기만 한다.** 갱신하지 않는다.
- 인덱스가 없거나 낡았으면 경고를 내고, 결과는 그대로 낸다. 막지 않는다.
- 경고에는 `engram reindex`를 함께 낸다.
- 낡음 판정은 문서별 경로, 크기, 수정 시각의 대조다.

harness의 검색 순위 비교는 항상 `reindex` 후 `search`를 돌린다. 그러지 않으면 비교 대상이 인덱스 상태에 좌우된다.

## 결과

- 조회 커맨드가 부작용을 갖지 않는다. 읽기 전용 위키에서도 검색이 동작한다.
- 인덱스 파일을 열어 순위 문제를 진단할 수 있다.
- 사용자가 `reindex`를 언제 돌려야 하는지 도구가 알려준다.
- 인덱스 크기가 원문의 5배를 넘으면 ADR 0010의 재검토 조건에 걸린다. 그때 형식도 함께 재검토한다.

## 열린 항목

- `doctor`가 인덱스 신선도를 점검 항목으로 다룰지. 지금은 조회 커맨드가 알리므로 중복이지만, 위키가 커지면 상시 점검이 필요해질 수 있다.
