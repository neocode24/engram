# 단계 디렉토리 안의 비문서 파일

## 배경

engram은 `page_dirs` 아래의 모든 `.md` 파일을 문서로 본다. `internal/walk`의 순회가 확장자만 보고 고르며, 스물네 곳에서 이 순회를 부른다.

실운영 위키 306문서에 처음 돌려 보니 `frontmatter.missing` 12건이 나왔고 그중 넷이 `README.md`였다.

```
context/README.md
inbox/README.md
inbox/_drop/README.md
sources/README.md
```

디렉토리가 무엇을 담는지 설명하는 파일이다. 프론트매터가 없는 것이 정상이며 위키 문서가 아니다. 나머지 여덟은 프론트매터가 빠진 실제 문서이므로 engram이 옳게 잡은 것이다.

**engram에는 "단계 디렉토리 안에 있지만 문서가 아닌 마크다운"이라는 개념이 없다.** `root_files`는 위키 루트에만 적용된다.

## 판단 근거

**README는 마크다운 저장소의 보편 관례다.** 특정 위키의 사정이 아니라 GitHub에서 디렉토리를 열면 렌더되는 파일이고, 어떤 마크다운 위키를 가져와도 나온다. 도구가 이 관례를 모르면 첫 실행에서 오탐을 낸다.

**막는 등급이라 더 문제다.** `frontmatter.missing`은 `error`이고 이 저장소의 `error`는 승급을 막는다. 디렉토리 설명 파일 때문에 승급이 막히면 사용자는 파일을 지우거나 도구를 버린다.

**순회에서 빼는 것이 검사에서 빼는 것보다 낫다.** lint에만 예외를 두면 `search`가 README를 색인하고 `graph`가 고아로 세고 `status`가 문서 수에 넣는다. 판정이 커맨드마다 갈린다. `internal/walk` 한 곳에서 빼면 스물네 곳이 함께 같은 답을 낸다. **같은 판정을 두 벌 두지 않는다**는 이 저장소의 원칙 그대로다.

**설정으로 연다.** README를 실제 위키 문서로 쓰는 사람이 있을 수 있다. 하드코딩하면 그 사람이 도구를 고쳐야 한다. 기본값을 제품이 강하게 제시하되 위키별로 바꿀 수 있게 한다. `min_wikilinks`를 다룬 방식과 같다([0009](0009-schema-presets-and-thresholds.md)).

**파일명으로 고른다. 경로가 아니다.** `README.md`는 어느 깊이에도 있다. 실측한 넷 중 하나가 `inbox/_drop/README.md`로 두 단계 아래에 있었다. 경로 목록으로 두면 하위 디렉토리를 만들 때마다 설정을 늘려야 한다.

**`root_files`와 합치지 않는다.** 성격이 반대다. `root_files`는 "루트에 반드시 있어야 하는 문서"이고 이것은 "어디에 있든 문서가 아닌 파일"이다. 하나는 존재를 요구하고 하나는 존재를 무시한다. 같은 키에 담으면 읽는 사람이 헷갈린다.

## 결정

**`engram.yaml`에 `ignore_files`를 두고 `internal/walk`의 순회에서 제외한다.**

| 항목 | 값 |
|---|---|
| 키 | `ignore_files` |
| 기본값 | `["README.md"]` |
| 대상 | `page_dirs` 아래 모든 깊이 |
| 판정 | 파일명(basename) 완전 일치 |
| 적용 지점 | `internal/walk`. 순회를 부르는 모든 커맨드가 함께 따른다 |

- 비우면(`ignore_files: []`) 아무것도 제외하지 않는다. README를 문서로 쓰는 위키가 그렇게 한다.
- `root_files`에는 영향을 주지 않는다. 루트 파일은 이름으로 명시되므로 제외 대상과 겹칠 일이 없다.
- `init`이 만드는 `engram.yaml`에 이 키를 주석으로 안내한다. 기본값이 있으므로 쓰지 않아도 동작한다.

## 결과

- 실운영 위키 306문서에서 `frontmatter.missing`이 12건에서 8건으로 준다. 남는 여덟은 프론트매터가 빠진 실제 문서이고 engram이 옳게 잡은 것이다.
- `search` 색인, 고아 판정, 문서 수 집계에서 README가 함께 빠진다. 순회 한 곳만 고쳤기 때문이다.
- 위키 문서 수가 줄어 보이는 변화가 생긴다. `status`의 문서 수가 이 결정 전후로 달라진다.
- 골든 픽스처에 README가 없으므로 스냅샷은 바뀌지 않는다. 순회 제외를 검증하는 테스트를 새로 넣는다.
