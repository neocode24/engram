# 저장소 구성과 Go 모듈명

## 배경

ADR 0001 시점의 저장소는 목적이 다른 네 가지를 1레벨 폴더에 나란히 두었다. `binary/`(제품 소스), `docs/`(설계 기록), `curriculum/`(강의 자료), `wiki/`(데모 위키)다. `docs/next-steps.md` 2번은 이것을 mono-repo로 유지할지 각각 별도 저장소로 뺄지를 미결로 남겼고, 그 미결 때문에 Go 모듈명이 정해지지 않아 코드 착수 자체가 막혀 있었다.

ADR 0004는 개인 GitHub에서 개발하고 사내 공개 시점에 Enterprise로 미러한다고 정했다. 즉 이 저장소는 언젠가 공개 경계를 넘는다. 구성 결정은 그 경계를 어디에 그을지와 같은 문제다.

## 판단 근거

**네 폴더는 대등하지 않다.** `binary/`, `docs/`, `curriculum/`은 사람이 쓰는 소스지만 `wiki/`는 `engram init`의 출력이다. 생성물을 소스와 같은 층위에 두면 "손으로 고쳐도 되는가"라는 질문이 영구히 남는다. 게다가 ADR 0005가 `harness/fixtures/`에 골든 위키를 두기로 했으므로, `wiki/`를 그대로 두면 성격이 같은 디렉토리가 둘이 된다.

**모듈 경로에 `binary`가 끼면 손해다.** 저장소 루트를 Go 모듈 루트로 삼으면 `go install github.com/neocode24/engram/cmd/engram@latest`가 관습대로 동작한다. `binary/` 아래에 모듈을 두면 경로에 의미 없는 마디가 붙거나 저장소 안에 모듈이 중첩되어 툴링이 계속 걸린다. 공개를 전제한 저장소에서 이것은 첫인상 비용이다.

**지금 저장소를 쪼개면 harness가 깨진다.** ADR 0005의 conformance 테스트는 upstream 계약과 Go 구현의 diff를 보는 장치다. 계약 스냅샷, 구현, parity 문서가 서로 다른 저장소에 흩어지면 그 diff가 저장소를 넘나들고 자동 갱신이 복잡해진다. 코드가 아직 없는 단계에서 얻을 이득도 없다.

**공개 경계는 폴더로 긋는다.** 파일마다 공개 여부를 판단하는 방식은 유지되지 않는다. 사내 한정 자료가 생기면 한 디렉토리에 모으고, 공개 전환 시 그 디렉토리만 들어내는 편이 기계적이고 안전하다.

**커리큘럼은 공개 자산이다.** 강의 자료에 사내 사례를 담지 않기로 했다. 사내 맥락이 필요한 부분은 Enterprise 저장소로 옮긴 뒤 거기서 덧붙인다. 따라서 커리큘럼은 격리 대상이 아니라 홍보 자산이며, 별도 폴더가 아니라 문서 체계 안에 둔다.

## 결정

**단일 저장소를 유지하고, 저장소 루트를 Go 모듈 루트로 삼는다.**

모듈명은 `github.com/neocode24/engram`, 실행 파일 진입점은 `cmd/engram`이다. Enterprise 미러로 옮겨도 모듈명은 바꾸지 않는다. 배포는 릴리스 아티팩트가 주 경로이고 `go install`은 보조이므로, 경로 불일치의 실익보다 이름 안정성이 크다.

디렉토리 구성은 아래로 한다.

| 경로 | 역할 | 성격 |
|---|---|---|
| `cmd/engram/` | 실행 파일 진입점 | 소스 |
| `internal/` | 구현 | 소스 |
| `harness/` | upstream 계약 스냅샷, 골든 픽스처, parity | 소스 + 검증 자산 |
| `docs/` | ADR, 설계, 여정, 로드맵 | 소스 |
| `docs/course/` | 강의 자료 | 소스, 공개 자산 |
| `examples/` | 데모 위키 | **생성물** |

`binary/`는 폐지한다. `wiki/`는 `examples/`로 옮기고 생성물로 못 박는다. `curriculum/`은 폐지하고 `docs/course/`로 옮긴다.

**`examples/`는 재생성 가능해야 한다.** `engram init --preset education`의 출력과 커밋된 내용이 달라지면 그것을 회귀로 간주한다. 즉 이 디렉토리는 예제인 동시에 테스트다. 반면 `harness/fixtures/`는 upstream 스크립트와 Go 구현의 출력을 비교하기 위한 고정 입력이며, 사람이 의도적으로 관리한다. 둘은 역할이 다르므로 합치지 않는다.

**사내 한정 자료가 생기면 `private/` 한 곳에 모은다.** 지금은 그런 자료가 없으므로 디렉토리를 만들지 않는다. 필요해지는 시점에 만들고, 공개 전환은 해당 경로를 이력에서 제거하는 방식으로 처리한다.

## 결과

- `docs/next-steps.md` 2번과 3번이 닫힌다. Go 스캐폴드 착수가 가능해진다.
- ADR 0004의 공개 경계가 파일 단위 판단에서 디렉토리 단위 규칙으로 바뀐다.
- ADR 0005의 harness가 단일 저장소 안에서 완결된다.
- 데모 위키가 문서에서 테스트로 승격된다. 대신 `init`이 결정적이어야 한다는 제약이 생기며, 이는 ADR 0005가 이미 정한 `--now` 요구와 같은 계열이다.

## 열린 항목

- Enterprise 미러 시점에 개인 저장소와 Enterprise 저장소 중 어느 쪽을 상류로 둘지. ADR 0004가 배포 채널만 정했고 개발 상류는 정하지 않았다.
- `docs/`가 ADR, 설계, 강의 자료를 모두 담으면서 커지면 분할이 필요할 수 있다. 강의가 실제로 굴러간 뒤 재검토한다.
