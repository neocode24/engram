# 0014 LLM과 engram의 역할 경계

## 결정

`engram` 바이너리는 **LLM을 호출하지 않는다.** LLM 프로바이더 설정, API key 저장, OAuth, 벤더 SDK 의존성을 두지 않는다.

호출 방향은 반대다. 사용자가 이미 사용 중인 LLM 에이전트(Claude Code, Hermes, Copilot 등)가 `engram` 커맨드를 부른다. 바이너리는 결정론적 연산과 계약 강제를 맡고, 판단과 문장 생성은 에이전트가 맡는다.

연결 수단은 `engram skills install`이다. 바이너리에 임베드된 스킬 문서를 감지된 에이전트의 스킬 디렉토리에 설치한다. 이것이 LLM 통합의 전부다.

## 근거

### 기능을 두 종류로 갈라 보면 경계가 드러난다

| 기능 | 성격 | 소유 |
|---|---|---|
| 승급 게이트 판정, lint, 스키마 검증 | 결정론적 규칙 | engram |
| BM25 검색, 링크 그래프, resurface 선정 | 결정론적 연산 | engram |
| digest 재료 수집, recall 청크 반환 | 결정론적 수집 | engram |
| 회의록 요약, inbox 트리아지 제안 | 판단과 문장 | 에이전트 |
| 연관 제안의 서술, 다이제스트 산문 | 판단과 문장 | 에이전트 |

아래 두 행에서 "재료를 모으는 부분"은 이미 위 세 행이다. 남는 것은 문장화뿐인데, 그 작업은 사용자가 이미 열어 둔 에이전트 세션 안에서 벌어진다.

### 바이너리가 LLM을 부르면 세션이 하나 더 열린다

사용자는 이미 에이전트 안에 있다. 그 상태에서 바이너리가 별도로 LLM을 호출하면 컨텍스트를 공유하지 못하는 두 번째 세션이 뜬다. 요금이 두 번 나가고, 사용자가 고른 모델과 다른 모델이 붙을 수 있으며, 대화 맥락을 잃은 채 같은 질문을 다시 받는다.

CLI를 서브프로세스로 실행하는 방식(`claude -p <prompt>`)도 같은 문제다. 호출 방향이 거꾸로다. 에이전트가 바이너리를 부르는 것이 자연스럽고, 바이너리가 에이전트를 부르는 것은 부모 세션을 버리는 행위다.

### 선행 사례가 이 구조를 이미 검증했다

이 프로젝트의 착상 원천인 도구는 Go 코드 전체에 LLM 프로바이더 호출이 한 건도 없다. 대신 스킬 문서 두 개를 바이너리에 임베드하고 `skills install`로 배포한다. 커맨드 주석과 불변식 문서가 같은 원칙을 명시한다. 재료 반환은 코드가, 판단과 산문은 에이전트가 한다.

### ADR 0001의 원칙이 그대로 적용된다

"판단은 사람이, 불변식은 코드가"에서 사람의 자리에 에이전트가 들어와도 경계는 이동하지 않는다. LLM이 관여하는 모든 지점의 산출물은 제안이며 확정은 사람이 한다. 따라서 LLM은 코어 기능이 아니라 바깥 층이다.

## 기각한 대안

| 대안 | 기각 근거 |
|---|---|
| 벤더 SDK 내장(anthropic-sdk-go, openai-go 등) | 프로바이더 수만큼 의존성과 breaking change가 붙는다. 정작 쓸 기능은 텍스트 왕복 하나뿐이다 |
| OAuth 직접 구현 | 콜백 서버, 토큰 저장, 리프레시를 프로바이더마다 다시 만들어야 한다. 각 벤더 CLI가 이미 하는 일이다 |
| OpenAI 호환 HTTP 단일 클라이언트 | 의존성 부담은 낮으나 구독제(API key 부재) 사용자를 지원할 수 없고, 자격증명 저장 책임이 생긴다 |
| CLI headless 서브프로세스 호출 | 호출 방향이 거꾸로다. 부모 에이전트 세션의 컨텍스트를 잃는다 |

셋째와 넷째 안은 검토 과정에서 한 번 채택 방향으로 정리되었다가 기각했다. 기각 시점의 결정적 근거는 "사용자가 이미 에이전트 안에 있다"는 사실이었다.

## 결과

### 얻는 것

- 바이너리가 자격증명을 보관하지 않는다. 유출 경로, 저장 위치 결정, `doctor`의 권한 점검 항목이 모두 사라진다.
- 바이너리 출력 전체가 결정론적이다. ADR 0005 harness의 골든 비교에 비결정성 예외를 뚫지 않아도 된다.
- 폐쇄망과 사내 프록시 환경에서 추가 통신 경로가 생기지 않는다.
- 사용자가 어떤 모델을 쓰든 engram은 관여하지 않는다.

### 지불하는 것

- 에이전트 없이 바이너리만 쓰는 사용자는 요약과 제안 기능을 얻지 못한다. 이는 결손이 아니라 설계된 경계다. 강의 초반 단위는 에이전트 없이 완결되어야 한다.
- 스킬 문서의 품질이 통합 품질을 그대로 결정한다. 커맨드를 고치면 스킬 문서도 같이 고쳐야 하며, 이 동기화는 자동화 대상이다.

### 커맨드 설계에 걸리는 제약

커맨드는 **완성된 산문이 아니라 재료를 반환하는 모양**이어야 한다. `digest`는 다이제스트 글이 아니라 창 안의 변경분과 태그와 결정 타임라인을 주고, `recall`은 요약이 아니라 청크 원문과 출처 슬러그를 준다. 이 규율이 깨지면 에이전트가 소비할 수 없는 출력이 나온다.

따라서 `--json`은 부가 기능이 아니라 **1급 출력 경로**다. 모든 조회 커맨드가 이를 지원해야 한다.

## 범위 밖

시맨틱 검색용 임베딩은 이 결정의 대상이 아니다. 벡터화는 생성 호출이 아니며 ADR 0007이 이미 선택 사이드카 층으로 분리했다. 그 결정은 그대로 유효하다.

## eject와의 관계

ADR 0013은 eject를 "규칙의 소유권 이양"으로 정의하고, 규칙은 파일로 내보낼 수 있으나 연산은 그럴 수 없다고 갈랐다. LLM 호출을 바이너리에서 빼면 이 분류에 회색 지대가 생기지 않는다. 프롬프트는 애초에 바이너리 안에 없고 에이전트 쪽 스킬 문서에 있으므로, 사용자가 고치고 싶으면 설치된 스킬 파일을 직접 고치면 된다. eject를 기다릴 필요가 없다.
