# pack의 반출 범위와 익명화

## 배경

여정 14가 이 커맨드의 자리다. "보고서, 블로그, 발표자료로 내보낸다. 익명화와 민감도 필터가 걸린다." 1.0에서 남은 마지막 커맨드이며 `docs/design.md`가 `pack`이라는 이름을 [0006](0006-dual-mode-eject-seal.md)부터 이 용도로 예약해 두었다.

정할 것이 셋이다. 무엇을 내보내는가, 어떤 형태로 내보내는가, 익명화를 무엇으로 하는가다.

첫째는 이미 답이 있다. [0044](0044-serve-is-read-only-and-shows-only-vetted-knowledge.md)가 "남에게 보이는 것"을 정했고 그 ADR이 스스로 `pack`을 후속 사용자로 지목했다. 나머지 둘이 이 문서의 몫이다.

## 판단 근거

### 노출 판정을 두 벌 두지 않는다

`serve`와 `pack`은 둘 다 위키를 밖으로 내보내는 문이다. 판정이 갈라지면 **`serve`가 감추는 문서를 `pack`이 내보내는 상태**가 되고, 그것은 민감도 선언을 도구가 뒤집는 것과 같다. 이 저장소는 게이트 판정과 고아 판정에서 같은 이유로 판정을 단일 함수로 유지해 왔다.

`internal/serve` 안에 있던 위치 판정과 제외 판정을 `internal/expose`로 옮기고 두 커맨드가 그것을 부른다. `serve`는 그 결과를 화면으로 만들고 `pack`은 파일로 쓴다. 옮기는 것이지 새로 쓰는 것이 아니므로 [0044](0044-serve-is-read-only-and-shows-only-vetted-knowledge.md)의 제외 규칙이 그대로 진실원이다.

명시 슬러그로 좁히는 경우에도 제외 규칙이 이긴다. 제외된 문서를 슬러그로 지목하면 반출하지 않고 왜 제외되었는지 알린다. 슬러그 지정이 민감도 필터를 뚫는 경로가 되면 "뒤집는 플래그를 두지 않는다"는 [0044](0044-serve-is-read-only-and-shows-only-vetted-knowledge.md)의 결정이 이름만 바뀌어 무력해진다.

### 형태를 바꾸지 않는다

설계 원칙 2가 "재료 반환"이다. 커맨드는 완성물이 아니라 재료를 준다.

보고서와 발표자료로 가려면 병합과 포맷 변환이 필요하고 블로그로 가려면 문서별로 남아야 한다. **셋을 한 형태로 만족시킬 수 없다.** 병합을 고르면 블로그 동선이 죽고 문서 경계와 위키링크가 뭉개진다. 반대로 문서별로 두면 pandoc 한 줄이 병합을 해결한다.

engram의 고유 가치는 **무엇을 내보낼지 고르는 것과 식별자를 지우는 것**이지 마크다운을 다른 포맷으로 바꾸는 것이 아니다. 포맷 변환기는 이미 세상에 있다.

압축도 하지 않는다. 압축하면 사용자가 나갈 내용을 확인하려고 다시 풀어야 하고 git으로 diff를 볼 수 없다. `zip -r`은 사용자가 친다.

### 익명화 사전을 내장하지 않는다

engram은 조직 어휘 목록을 담을 수 없다. 그것이 [0024](0024-public-boundary-and-private-directory.md)가 그은 공개 경계이고 [0029](0029-upstream-vendoring-and-parity-execution.md)가 upstream 규칙 명세를 vendoring할 때 쓴 방식이다. 1.1의 용어 정규화도 같은 자세로 간다. **메커니즘만 주고 사전은 쓰는 사람이 채운다.**

치환 파일 형식은 이 저장소가 자기 vendoring에 이미 쓰고 있는 것과 같다. 한 줄에 `원문==>대체어` 하나이고 `#`으로 시작하는 줄과 빈 줄은 무시한다. 형식을 새로 만들 이유가 없다.

**치환 파일이 없으면 치환하지 않는다.** 익명화를 강제하면 사전이 없는 사용자가 반출을 못 하고, 그러면 `cp -r`로 우회한다. 우회로가 생기면 민감도 필터도 함께 빠진다. 대신 치환하지 않았다는 사실을 매번 알린다.

**본문과 프론트매터와 파일명 전부를 치환한다.** 본문만 하고 파일명을 두면 `사내제품명-로드맵.md`가 그대로 나간다. 파일명을 치환하면 위키링크는 본문에 있으므로 같은 치환을 함께 받아 이름이 어긋나지 않는다.

치환 순서는 원문 길이 내림차순이고 같으면 사전순이다. 겹치는 규칙이 있을 때 긴 쪽이 먼저 걸려야 하고 순서가 결정론이어야 하기 때문이다.

규칙별 적용 건수를 낸다. **한 번도 걸리지 않은 규칙을 따로 알린다.** 사전에 오타가 있으면 조용히 통과하는데 그것이 익명화 실패의 가장 흔한 형태다.

### 번들 밖 링크는 그대로 둔다

`serve`는 제외 문서를 가리키는 위키링크를 링크로 만들지 않는다. 클릭 가능한 URL이 곧 새는 경로이기 때문이다. `pack`은 다르다. 파일이 번들에 없으면 링크는 자연히 열리지 않으므로 내용이 새지 않는다. 슬러그에 든 식별자는 치환 파일이 맡는다.

본문을 도구가 고치면 사용자가 반출물을 열었을 때 자기가 쓴 것과 다른 문장을 본다. 그대로 두고 **번들 밖을 가리키는 링크 수를 알린다.**

### 되돌릴 수 없으므로 미리 본다

반출물이 밖으로 나가면 회수가 없다. `--dry-run`을 둔다. `eject`와 같은 성격이다.

출력 디렉토리가 비어 있지 않으면 거절한다. 이전 반출의 잔재가 섞이면 이번에 무엇이 나갔는지 아무도 모른다. 덮어쓰는 플래그를 두지 않는다. 지우는 것은 사용자가 자기 눈으로 보고 한다.

## 결정

**`engram pack`은 노출 규칙을 통과한 문서를 마크다운 그대로 디렉토리에 내보내고 익명화는 사용자가 준 치환 파일로 한다.**

| 항목 | 값 |
|---|---|
| 출력 | `--out` 디렉토리에 마크다운. **병합도 압축도 포맷 변환도 하지 않는다** |
| 기본 대상 | [0044](0044-serve-is-read-only-and-shows-only-vetted-knowledge.md)의 노출 규칙 그대로. `context/`와 `root_files` |
| 좁히기 | 위치 인자로 슬러그를 준다. 링크를 따라가지 않는다 |
| `inbox/`, `sources/` | 제외. 뒤집는 플래그를 두지 않는다 |
| `archive/` | 기본 제외. `--include-archive`로 연다 |
| 민감도 | `private-local-only`와 `restricted` 제외. **명시 슬러그도 뚫지 못한다** |
| 익명화 | `--replacements` 파일. `원문==>대체어` 한 줄에 하나. **없으면 치환하지 않고 그 사실을 알린다** |
| 치환 범위 | 본문, 프론트매터, 파일명 전부 |
| 치환 순서 | 원문 길이 내림차순, 같으면 사전순 |
| 프론트매터 | 그대로 나간다. 축을 깎지 않는다 |
| 번들 밖 링크 | 그대로 둔다. 수를 알린다 |
| 출력 디렉토리 | 비어 있지 않으면 거절. 덮어쓰는 플래그를 두지 않는다 |
| `--dry-run` | 있다. 기본은 아니다 |
| 디렉토리 구조 | 위키 상대 경로를 유지한다 |

- 노출 판정은 `internal/expose`가 유일한 진실원이며 `serve`와 `pack`이 함께 부른다.
- 실행할 때마다 무엇이 나가고 무엇이 빠졌는지, 치환이 몇 건 걸렸는지 낸다. `serve`가 시작할 때 노출 집계를 내는 것과 같은 자세다.
- 걸리지 않은 치환 규칙이 있으면 경고한다. 종료 코드는 바꾸지 않는다.

## 결과

- 1.0의 커맨드 범위가 닫힌다.
- 노출 판정이 패키지 하나로 모여 `serve`와 `pack`이 갈라질 수 없다. 판정을 고치면 양쪽이 함께 움직인다.
- 익명화 품질은 사용자 사전의 품질이다. engram은 사전이 비었는지 걸리지 않았는지만 알린다. **도구가 식별자를 알아서 찾아 주지 않는다.**
- 포맷 변환을 하지 않으므로 발표자료 동선에는 pandoc 같은 도구가 한 단계 더 붙는다.
- 1.1의 용어 정규화가 같은 치환 형식을 쓸 수 있다. 사전 파서가 재사용 지점이다.
