# sync의 범위

## 배경

`sync`를 말하는 문서가 넷인데 둘로 갈린다.

| 출처 | 무엇이라 말하나 |
|---|---|
| ADR [0009](0009-schema-presets-and-thresholds.md) | `updated`와 `sourced_at`을 git 이력에서 채우는 도구 |
| ADR [0032](0032-update-writes-the-updated-field.md) | git 이력으로 `updated`를 정정하는 일 |
| `docs/design.md` | "git 기반 동기화. 프론트매터 병합" |
| `docs/journeys.md` 여정 13 | 2대 PC를 git으로 맞춘다. 프론트매터 병합을 지원해야 한다 |

앞의 둘은 **날짜 필드를 채우는 일**이고 뒤의 둘은 **병합 충돌을 푸는 일**이다. 구현 착수 시점에 둘 중 무엇인지 정해야 한다.

## 판단 근거

**동등성 검증의 셋째 축이 이 커맨드의 대조 대상을 이미 지목한다.** ADR [0005](0005-upstream-contract-and-harness.md)가 비교 축 넷을 정하면서 셋째를 "frontmatter 정규화, upstream `scripts/sync_updated_field.py`, engram 해당 커맨드 없음"으로 적었다. **그 스크립트가 하는 일이 날짜를 채우는 것이다.** `sync`가 병합을 맡으면 이 축은 영원히 대조 대상이 없다.

**성격이 다르다.** 날짜 정정은 git 이력이 진실원이고 같은 저장소 상태에 같은 결과를 낸다. 결정론적이므로 골든 비교가 성립한다. 병합은 두 갈래 변경을 놓고 무엇을 남길지 고르는 일이라 결정론이 성립하지 않는 자리가 있다. 이 저장소는 결정론적인 것만 코드가 강제한다([0014](0014-llm-boundary-agent-drives-binary.md)).

**병합은 커맨드가 아니다.** git이 병합을 다루는 자리는 merge driver이며 `.gitattributes`와 `merge.<driver>.driver` 설정으로 등록하는 물건이다. 사용자가 `engram sync`를 치는 것이 아니라 `git merge` 도중 git이 부른다. 진입점이 다르므로 같은 커맨드에 담으면 둘 다 어색해진다.

**`created`는 git이 모른다.** 0009가 `created`를 "원본이 처음 기록된 날. 회의한 날, 문서가 쓰인 날"로 정의했다. 수년 전 자료를 오늘 이관하면 git 최초 커밋일은 오늘이지만 `created`는 수년 전이다. **git에서 유추하면 그 구분이 무너진다.** `sourced_at`이 편입일이고 그것이 git 최초 커밋일이다.

**`--dry-run`을 기본으로 한다.** 문서 수백 개의 프론트매터를 한 번에 바꾸는 커맨드다. 여정 12가 `migrate`에 대해 같은 판단을 했고 성격이 같으므로 같게 둔다. 되돌릴 수 있다는 것(git)이 되돌릴 필요가 없다는 뜻은 아니다.

**커밋되지 않은 파일은 건너뛴다.** git 이력이 없으므로 채울 값이 없다. 실패로 다루면 새 문서를 만든 직후 `sync`가 항상 실패한다. 건너뛰고 개수를 알린다.

## 결정

**`sync`는 git 이력에서 날짜 필드를 정정한다. 프론트매터 병합은 이 커맨드가 맡지 않는다.**

| 필드 | 채우는 값 | 제외 |
|---|---|---|
| `updated` | 그 파일의 **마지막** 커밋 날짜 | `sources/` 계층([0009](0009-schema-presets-and-thresholds.md)) |
| `sourced_at` | 그 파일의 **최초** 커밋 날짜 | 축이 꺼진 경우 |
| `created` | **건드리지 않는다** | 전부 |

- `--dry-run`이 기본이다. 실제로 쓰려면 `--apply`를 준다.
- 값이 이미 같으면 쓰지 않는다. 두 번 돌려도 같은 결과다.
- git이 없거나 위키가 git 저장소가 아니면 실패하고 설치나 `git init`을 안내한다.
- 커밋되지 않은 파일은 건너뛰고 개수를 알린다. 실패로 다루지 않는다.
- 워킹트리가 더러워도 돈다. 판정 근거가 커밋 이력이라 작업 중인 변경과 무관하다.
- 파일 이름이 바뀐 이력은 git이 따라가는 만큼만 따라간다. 추적 옵션을 켜지 않는다. 사용자가 `engram mv`를 쓰면 그 커밋이 마지막 커밋이 되므로 실사용에서 문제가 되지 않는다.

**프론트매터 병합은 별도로 판단한다.** 여정 13의 후반부이며 git merge driver로 성립한다. 0.4 범위에 넣지 않는다.

## 결과

- 동등성 검증의 셋째 축이 대조 대상을 얻는다. upstream `sync_updated_field.py`와 `engram sync`의 결과를 같은 위키에서 비교할 수 있다.
- ADR 0032가 `update` 시점에 채운 `updated`를 git 이력이 덮는다. 0032가 예고한 그대로다.
- git 없이 쓰는 위키는 `sync`를 못 쓴다. 그 위키에서도 `update`가 `updated`를 채우므로 재발견은 계속 동작한다. 0032가 이 경우를 이미 다뤘다.
- `internal/doctor`가 git 부재를 경고로만 다루는 근거가 바뀐다. 지금은 "구현된 커맨드가 전부 git 없이 동작하기 때문"인데 `sync`가 생기면 그 문장이 사실이 아니게 된다. 경고 문구를 고친다.
- 여정 13이 절반만 덮인다. 남은 절반(병합)은 미결로 남는다.
