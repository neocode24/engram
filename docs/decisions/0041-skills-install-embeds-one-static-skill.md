# skills install이 무엇을 심는가

## 배경

ADR [0014](0014-llm-boundary-agent-drives-binary.md)가 LLM 통합의 전부를 `engram skills install` 하나로 정했다.

> 바이너리에 임베드된 스킬 문서를 감지된 에이전트의 스킬 디렉토리에 설치한다. 이것이 LLM 통합의 전부다.

구현 착수 시점에 셋이 정해져 있지 않다. **문서에 무엇을 쓰는가, 어디에 심는가, 위키마다 다른 규칙을 어떻게 알리는가.**

## 판단 근거

### 스킬 문서는 정적이다

위키마다 임계값과 축이 다르다. 스킬 문서가 그 값을 담으면 위키를 옮길 때마다 다시 심어야 하고, 설정을 바꾸면 문서가 낡는다.

**스킬 문서는 engram을 다루는 법을 가르치고, 그 위키의 규칙은 에이전트가 `engram rules show`로 직접 얻게 한다.** 규칙의 진실원은 이미 그 커맨드다([0013](0013-eject-redefined-seal-removed.md)). 사본을 하나 더 만들지 않는다.

이 분리는 `eject`와 반대 방향이라는 점에서 일관된다. `eject`는 그 위키의 설정을 반영해 파일을 **생성**하고([0039](0039-eject-emits-rule-specs-and-a-python-linter.md)), `skills install`은 위키와 무관한 문서를 **심는다.** 전자는 위키에, 후자는 에이전트에 놓인다.

### 하나로 시작한다

문서를 여럿으로 나누면 에이전트가 어느 것을 언제 읽어야 하는지 판단해야 한다. engram의 커맨드 스물넷은 다섯 갈래로 이미 정리되어 있고 한 문서에 들어간다. **나눌 이유가 생기면 그때 나눈다.**

### 문서가 반드시 담아야 할 것

에이전트가 이 문서만 읽고도 경계를 어기지 않아야 한다.

**호출 방향.** engram은 LLM을 부르지 않는다. 에이전트가 engram을 부른다. 이것을 모르면 에이전트가 engram에게 요약을 시키려 든다.

**쓰기 경계.** 에이전트가 쓸 수 있는 곳은 `inbox`까지다. `context`로 올리려면 승급 게이트를 지나야 하고 확정은 사람이 한다(여정 8). 이 한 줄이 다른 PKM 연동과의 차별점이다.

**`--json`이 주 경로다.** 조회 커맨드는 완성된 산문이 아니라 재료를 낸다. 문장화는 에이전트의 몫이다.

**`--now`의 뜻.** 기준 시각을 고정하는 플래그이며 에이전트가 재현 가능한 결과를 원할 때 쓴다.

**규칙은 `rules show`로 얻는다.** 임계값과 허용값을 지어내지 말라고 명시한다.

### 감지에 실패하면 묻지 않고 알린다

에이전트 스킬 디렉토리 규약은 도구마다 다르고 바뀐다. 목록을 코드에 박으면 곧 낡는다.

**디렉토리가 실제로 있는 것만 대상으로 본다.** 없으면 만들지 않는다. 없는 도구를 위해 디렉토리를 만들면 그 도구를 쓰지 않는 사용자의 홈에 빈 디렉토리가 생긴다.

하나도 못 찾으면 **실패하고 `--dir`를 안내한다.** 조용히 아무것도 안 하고 성공을 알리는 것이 최악이다.

### 덮어쓰지 않는다

사용자가 스킬 문서를 고쳤을 수 있다. `eject`와 같은 판단이다([0039](0039-eject-emits-rule-specs-and-a-python-linter.md)). 충돌하면 알리고 멈추며 `--force`로만 덮는다.

## 결정

**`engram skills install`은 바이너리에 임베드된 정적 스킬 문서 하나를 감지된 에이전트 디렉토리에 심는다.**

| 항목 | 값 |
|---|---|
| 문서 수 | 하나 |
| 내용 | engram을 다루는 법. 위키별 값은 담지 않는다 |
| 위키별 규칙 | 에이전트가 `engram rules show --json`으로 얻는다 |
| 대상 | 실제로 존재하는 에이전트 스킬 디렉토리만 |
| 감지 실패 | 실패하고 `--dir`를 안내한다 |
| 충돌 | 덮지 않고 멈춘다. `--force`로만 덮는다 |
| `--dry-run` | 어디에 무엇을 심을지만 낸다 |

스킬 문서가 반드시 담는 것은 다섯이다. 호출 방향, 쓰기 경계(`inbox`까지), `--json`이 주 경로라는 것, `--now`의 뜻, 규칙은 `rules show`로 얻는다는 것.

- 대상 디렉토리 목록은 코드 한 곳에 두고 주석에 출처를 남긴다. 규약이 바뀌면 그 한 곳을 고친다.
- 위키를 인자로 받지 않는다. **이 커맨드는 위키가 아니라 에이전트를 다룬다.** 위키 밖에서 실행해도 동작해야 한다.

## 결과

- 여정 23(easy 모드 에이전트 연동)이 성립한다. 커리큘럼의 마지막 단위가 이 커맨드를 쓴다.
- 스킬 문서가 위키 설정과 무관하므로 한 번 심으면 모든 위키에 통한다.
- 에이전트가 임계값을 알려면 `rules show`를 불러야 한다. 왕복이 한 번 늘지만 값이 낡지 않는다.
- MCP 노출(여정 8)은 별개의 경로로 남는다. 두 경로가 같은 쓰기 경계를 지켜야 하므로 MCP를 만들 때 이 문서의 경계 문구를 진실원으로 삼는다.
- `engram --help`가 커맨드 목록의 진실원이라는 계약이 유지되므로 스킬 문서에 커맨드 목록을 통째로 베끼지 않는다.
