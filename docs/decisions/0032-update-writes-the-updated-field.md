# update가 updated를 채운다

## 배경

ADR [0009](0009-schema-presets-and-thresholds.md)가 날짜 축 셋을 정하면서 `updated`를 "도구. git 이력에서 채운다. 손으로 쓰지 않는다"로 두었다. 그 도구가 `sync`이고 `sync`는 0.4 마일스톤이다.

0.3까지 구현한 스무 커맨드 중 `updated`를 쓰는 것은 `archive` 하나다. 문서의 프론트매터와 본문을 바꾸는 `update`는 쓰지 않는다. **`engram update`로 문서를 고쳐도 `updated`가 그대로다.**

`resurface`와 `digest`의 노후 판정이 이 필드를 읽는다. `internal/resurface`의 `BaseDate`가 `updated`를 우선하고 없으면 `created`로 물러난다. 지금은 거의 모든 문서에 `updated`가 없으므로 사실상 전부 생성일로 판정한다. 어제 고친 문서와 1년 전에 만들고 손대지 않은 문서가 같은 취급을 받는다. **오래 안 본 문서를 다시 꺼낸다는 커맨드의 존재 이유가 성립하지 않는다.**

## 판단 근거

**`sync`를 기다리면 두 마일스톤 동안 재발견이 잘못 돈다.** 0.3의 재발견 커맨드 셋(`resurface`, `bridge`, `digest`)이 이미 사용자 앞에 있다. 그중 둘이 노후를 읽는다. 0.4가 올 때까지 잘못된 목록을 내는 커맨드를 그대로 두는 선택지는 없다.

**`sync`가 있어도 이 문제는 남는다.** `sync`는 git을 요구한다. `internal/doctor`가 지금 git 부재를 경고로만 다루는 이유가 "구현된 커맨드가 전부 git 없이 동작하기 때문"이다. git 밖에서 쓰는 위키는 `sync`가 와도 `updated`를 영원히 못 얻는다. 그리고 git이 있어도 `sync`를 돌리기 전까지는 값이 낡아 있다.

**두 writer가 충돌하지 않는다.** `sync`가 git 이력에서 읽은 값이 더 정확하므로 나중에 덮어쓴다. 이 결정은 `sync`의 권위를 내리지 않는다. `sync`가 오기 전과 git 밖에서의 빈자리를 채울 뿐이다.

**도구가 채우는 것은 0009의 계약 안이다.** 0009가 금지한 것은 사람이 손으로 쓰는 것이다. `update`는 도구다. 바뀌는 것은 "git 이력에서만"이라는 경로의 배타성이지 주체가 아니다.

**sources는 제외한다.** 0009가 "`sources/`에는 `updated`를 넣지 않는다"고 못 박았고 `internal/lint`의 `sources.updated` 규칙이 그것을 warn으로 잡는다. 예외를 두지 않으면 `engram update`가 만든 문서를 `engram lint`가 지적한다. 이 저장소에서 같은 계열의 결함이 다섯 번 났다. 여섯 번째를 만들지 않는다.

**사용자가 명시한 값이 이긴다.** `--set updated=<값>`과 `--unset updated`는 사용자가 이 필드를 알고 손대는 경우다. 자동 채움이 그 뒤에 덮으면 두 플래그가 무력해진다. 이관한 자료의 실제 갱신일을 적는 것이 정당한 용례다.

**프론트매터만 바꿔도 채운다.** 0009의 정의는 "마지막으로 내용이 갱신된 날"이고 태그 추가는 본문 변경이 아니다. 그러나 둘을 가르면 분기가 하나 늘고, `sync`가 볼 git 커밋 시각은 애초에 그 둘을 구분하지 않는다. 나중에 `sync`가 덮어쓸 값과 판정 기준을 다르게 두지 않는다.

## 결정

**`engram update`가 문서를 쓸 때 `updated`를 전역 `--now` 기준 날짜로 채운다.**

| 항목 | 값 |
|---|---|
| 채우는 시점 | 파일을 쓰기 직전 |
| 값 | 전역 `--now` 기준 날짜. 형식 `YYYY-MM-DD` |
| 제외 | sources 계층 문서 |
| 제외 | `--set updated=<값>`을 준 경우 |
| 제외 | `--unset updated`를 준 경우 |

- 자동으로 채운 사실을 사람이 읽는 출력과 `--json` 결과에 남긴다. 사용자가 요청하지 않은 변경이므로 알리지 않고 하지 않는다.
- `sync`가 오면 git 이력이 이 값을 덮는다. `sync`가 이 필드의 최종 권위다.
- `resurface`의 "마지막 갱신" 표현은 그대로 둔다. `updated`가 없는 문서는 한 번도 갱신되지 않은 문서이고, 그 문서의 마지막 갱신 시점은 생성 시점이다. `created`로 물러나는 동작이 표현과 어긋나지 않는다.

## 결과

- `engram update`로 고친 문서가 `resurface` 후보에서 빠진다. 재발견 루프가 의도한 신호를 낸다.
- `digest`의 노후 집계가 실제 활동을 반영한다. `internal/digest`가 `resurface.IsStale`을 그대로 쓰므로 함께 고쳐진다.
- sources 문서는 `update`로 고쳐도 `updated`가 생기지 않는다. 원본 보존 계층의 신선도를 오해하게 만들지 않는다.
- 0.4의 `sync`는 이 필드를 만드는 일이 아니라 git 이력으로 정정하는 일이 된다. 범위가 줄어든다.
- git 밖에서 쓰는 위키도 재발견이 동작한다.
