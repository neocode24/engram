# 에이전트가 게이트 통과 여부를 짐작하고 있었다

## 배경

[0055](0055-agents-change-the-wiki-only-through-commands.md)로 파일 직접 편집을 막은 뒤 실제 에이전트가 처음으로 규약대로 움직였다. 파일을 만들지 않았고, `search`로 이을 곳을 찾았고, 없다고 판단했을 때 문서를 지어내지 않았고, `promote`를 실행하지 않고 제안하고 멈췄다.

그런데 제안이 틀렸다.

```
# 1. 새벽 응답 지연 사고 (첫 문서, 유예 규칙 적용)
engram promote .../inbox/2026-08-17-test.md --type incident --slug 응답-지연-사고-2026-03-04

참고: 첫 문서는 위키가 비어있어서 유예 규칙으로 통과합니다
```

그대로 돌리면 거절된다.

```
Error: 승급 게이트를 넘지 못했습니다: 이어지는 위키링크가 0개로 min_wikilinks 2개에 못 미칩니다
```

그 위키에는 `index.md`와 `sources/` 문서가 있어 대상이 둘이다. 유예는 대상이 기준보다 **적을 때**만 걸리므로 2 < 2가 아니라 안 걸린다. 에이전트는 "`context`가 비었다"를 "위키가 비었다"로 읽고 유예를 넘겨짚었다.

같은 실수가 세 번째다. [0054](0054-gate-counts-only-links-that-resolve.md)를 쓰게 만든 실행에서도 에이전트가 "게이트 요구 링크 수는 본문 링크로 이미 충족"이라고 틀리게 단언했다.

## 판단 근거

**문서로 고칠 수 있는 종류가 아니다.** 0052, 0054, 0055가 전부 스킬 문서에 문장을 더하는 것으로 끝났다. 그런데 게이트 통과 여부는 규칙을 아는 것과 별개다. **위키의 현재 상태를 계산해야 나오는 값**이고, 그 계산을 하는 것은 `lint.EvaluateGate` 하나다. 에이전트에게 그 계산을 머릿속으로 다시 하라고 요구하는 구조가 잘못이다.

**같은 계산을 두 벌 두지 않는다는 원칙과 같은 자리다.** 0054가 집계 함수를 하나로 모은 이유가 "판정을 여러 벌 두면 커맨드로 통과한 문서를 lint 가 거절한다"였다. 에이전트의 추론은 그 두 번째 벌이다.

**쓰기 전에 확인하는 수단이 이미 있다.** `mv --dry-run`이 무엇이 바뀔지 먼저 낸다. `eject`와 `export`도 같다. **위키를 바꾸는 커맨드 중 `promote`만 없었다.** 승급은 파일을 옮기고 원본을 지우는 가장 무거운 쓰기인데 미리 볼 수단이 없었다.

**사람에게도 이롭다.** 승급 결정은 사람의 것이다([0043](0043-mcp-exposes-one-write-tool-and-omits-promote.md)). 실행 전에 무엇이 만들어질지 볼 수 있어야 결정이다.

**MCP에는 안 낸다.** 0043의 도구 목록은 그대로다. `promote`가 없으므로 `--dry-run`도 갈 자리가 없다.

## 결정

`promote`에 `--dry-run`을 더한다.

검사는 전부 돈다. 문서 존재, 단계, 문서 종류 허용값, 대상 파일 충돌, 게이트다. 게이트가 막으면 **시험 실행도 똑같이 거절한다.** 통과하면 무엇이 만들어질지 내고 아무것도 쓰지 않는다.

```
올릴 예정입니다: inbox/2026-08-17-test.md에서 context/응답-지연.md로
문서 종류: incident
게이트: 링크 2개, 대상 2개, 기준 2개
시험 실행이라 아무것도 쓰지 않았습니다
```

`--json`은 같은 결과에 `dryRun: true`를 더해 낸다.

스킬 문서의 3단계를 바꾼다. "실행 가능한 한 줄로 제안한다"가 "`--dry-run`으로 검증한 뒤 제안한다"가 된다. **게이트 통과 여부를 짐작하지 말라고 명시하고, 검증하지 않은 커맨드를 사람에게 넘기지 말라고 적는다.**

## 결과

- 에이전트가 자기 제안을 스스로 검증한다. 틀린 제안이 사람에게 오지 않는다.
- 거절당하면 거절 메시지를 읽고 `--related`를 고쳐 다시 돌릴 수 있다. 아무것도 쓰지 않으므로 몇 번이든 된다.
- 사람도 승급 전에 무엇이 만들어질지 본다.
- 회귀 시험 둘을 더했다. 통과 시 파일을 안 만들고 `inbox` 원본도 안 지우는지, 게이트가 막으면 시험 실행도 거절하는지다.

## 열린 항목

- `demote`, `archive`, `new`에도 `--dry-run`을 둘지. `demote`는 링크가 깨지는 목록을 실행 전에 경고로 이미 내고, `archive`는 슬러그를 유지해 되돌리기 쉽다. `new`는 지우면 그만이다. 요구가 나오면 그때 본다.
- **`inbox`에서 `sources`로 가는 경로가 없다.** 같은 실행에서 에이전트가 원본 보존이 필요하다고 판단하고 `engram source ... < inbox 파일`을 제안했다. 프론트매터가 붙은 파일을 표준 입력에 넣는 것이라 본문에 옛 프론트매터가 박히고 `inbox` 원본도 안 지워져 같은 내용이 두 곳에 남는다. `demote`는 `context`에서만 내려간다. 이 자리가 비어 있어 에이전트가 잘못된 우회를 만들어 낸다.
