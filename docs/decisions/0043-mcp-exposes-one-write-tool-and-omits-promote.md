# MCP 노출의 도구 분해

## 배경

여정 8이 위키를 MCP 서버로 노출하기로 하면서 쟁점을 하나로 좁혔다.

> 쟁점은 쓰기 권한 범위다. 에이전트가 `context`에 직접 쓰면 승급 게이트 철학이 무너지므로 **MCP 쓰기는 inbox까지만 허용하고 승급은 사람 확인을 강제한다.** 이것이 다른 PKM MCP와의 차별점이 된다.

`docs/design.md`가 "MCP 노출 시 도구 단위 분해"를 열린 항목으로 남겼다. 경계는 확정이고 분해가 미결이다.

구현 방식도 정해지지 않았다. 프로토콜을 직접 구현할지 공식 SDK를 쓸지다.

## 판단 근거

### 도구는 커맨드가 아니라 에이전트가 하려는 일 단위다

커맨드 스물다섯을 그대로 도구 스물다섯으로 내보내면 셋이 무너진다. 에이전트가 고를 것이 너무 많고, 쓰기 경계가 도구마다 흩어져 목록만 봐서는 안전한지 알 수 없고, `init`이나 `eject`처럼 MCP 세션에서 부를 이유가 없는 것이 섞인다.

### 쓰기 도구를 하나만 둔다

**`capture` 하나다.** `inbox`에만 쓴다.

경계를 문서로 설명하는 것과 도구 목록으로 드러내는 것은 다르다. 쓰기 도구가 하나뿐이고 그것이 `inbox`에만 쓰면 **도구 목록을 훑는 것만으로 경계가 읽힌다.** 설명을 읽지 않은 에이전트도 어길 수단이 없다.

`source`는 노출하지 않는다. `sources/`는 원본 보존 계층이라 `inbox`보다 위이고, 여정 8의 경계는 `inbox`까지다. 원본 확정은 사람이 출처를 확인하고 하는 일이다.

### promote를 내보내지 않는다

ADR [0041](0041-skills-install-embeds-one-static-skill.md)이 심는 스킬 문서가 이렇게 말한다.

> promote를 제안할 수 있지만 실행은 사람에게 맡겨라.

**MCP에 `promote` 도구가 있으면 그 문장이 무의미해진다.** 에이전트가 스스로 승급을 실행할 수 있는데 하지 말라고 적어 두는 것은 규칙이 아니라 부탁이다. 이 저장소는 강제할 수 있는 것을 부탁으로 두지 않는다.

같은 이유로 `demote`, `archive`, `new`, `mv`, `update`, `migrate`, `sync`도 내보내지 않는다. 전부 위키의 파일을 바꾼다.

### 조회 도구는 상태를 쓰지 않는다

`resurface`는 제시 이력을 쓰는 유일한 조회 커맨드다([0028](0028-rediscovery-state-and-boundaries.md)). MCP 도구로 노출할 때는 `--dry-run`에 해당하는 동작으로 고정한다. **에이전트가 위키를 훑는 것만으로 사람의 재발견 이력이 오염되면 안 된다.**

### 위키 경로를 서버 시작 시 고정한다

MCP 서버는 장기 실행 프로세스다. 도구 인자로 위키 경로를 받으면 에이전트가 임의 디렉토리를 읽을 수 있다. **경로를 인자로 두는 것은 파일 시스템 읽기 권한을 여는 것과 같다.** 시작 시 하나로 고정하고 도구는 경로를 받지 않는다.

### 공식 SDK를 쓴다

측정했다. stdio 전용 최소 서버를 만들어 실제로 링크되는 것을 봤다.

| 항목 | 값 |
|---|---|
| 링크되는 외부 모듈 | 9. `golang.org/x/oauth2` 포함 |
| 최소 서버 바이너리 | 8.6MB |
| 현재 engram 바이너리 | 6.5MB |

**비용이 있다. 쓰지 않는 `oauth2`가 바이너리에 들어온다.** HTTP transport 때문이며 stdio만 쓰는 우리에게는 죽은 코드다.

그럼에도 SDK를 택한다. **MCP는 상호운용이 전부다.** 외부 클라이언트가 붙지 않으면 이 기능은 0이고, 스펙 일탈이 곧 실패다. ADR [0010](0010-storage-index-and-korean-search.md)이 BM25를 직접 구현한 이유는 "랭킹을 소유해야 동등성 검증을 보증할 수 있다"였는데, 그것은 **우리의 판정**이라 소유가 필요했다. MCP는 남의 규약이고 소유해서 얻는 것이 없다. 손으로 짜면 스펙이 바뀌었는지 알 방법도 없다.

`oauth2`가 링크되는 것과 engram이 OAuth를 하는 것은 다르다. ADR [0014](0014-llm-boundary-agent-drives-binary.md)가 금지한 것은 LLM 프로바이더 인증을 바이너리가 떠안는 일이며 그 사실은 바뀌지 않는다. 다만 죽은 코드가 들어온다는 점은 비용으로 기록한다.

### 판정을 두 벌 두지 않는다

MCP 도구는 CLI와 같은 `internal/` 패키지를 부른다. 도구 안에서 규칙을 다시 판정하지 않는다. 같은 판정이 두 곳에 생기면 CLI로 통과한 문서를 MCP가 거절하는 상태가 된다.

## 결정

**`engram mcp`가 stdio로 MCP 서버를 띄운다. 도구는 열이며 그중 쓰기는 하나다.**

| 도구 | 성격 | 비고 |
|---|---|---|
| `capture` | **쓰기** | `inbox`에만 쓴다. 유일한 쓰기 도구 |
| `search` | 읽기 | 문서 목록 |
| `recall` | 읽기 | 인용할 원문 조각 |
| `backlinks` | 읽기 | 들어오는 링크 |
| `status` | 읽기 | 위키 현황 |
| `lint` | 읽기 | 규칙 위반 |
| `rules` | 읽기 | 이 위키에 적용되는 규칙 |
| `resurface` | 읽기 | 제시 이력을 쓰지 않는다 |
| `bridge` | 읽기 | 기각을 기록하지 않는다 |
| `digest` | 읽기 | 기간 집계 |

- **전송은 stdio 하나다.** HTTP는 인증과 네트워크 노출을 부르며 `serve`의 영역이다.
- 위키 경로는 `engram mcp --wiki <경로>`로 시작 시 고정한다. **도구는 경로를 받지 않는다.**
- 도구 결과는 `--json` 출력과 같은 구조를 낸다. 형식을 두 벌 두지 않는다.
- 판정은 `internal/` 패키지를 그대로 부른다.
- 구현은 공식 Go SDK를 쓴다.
- `--now`를 도구 인자로 두지 않는다. 재현이 필요하면 CLI를 쓴다.

## 결과

- 다른 PKM MCP와의 차별점이 도구 목록에서 바로 읽힌다. 쓰기가 하나이고 승급이 없다.
- 에이전트가 승급을 실행할 수단이 없으므로 스킬 문서의 "실행은 사람에게 맡겨라"가 부탁이 아니라 사실이 된다.
- 바이너리가 커진다. 붙이기 전 6.5MB에서 붙인 뒤 11.4MB가 되었다. 실측값이다. 단일 바이너리 배포에서 이 크기 차이가 설치 경험을 바꾸지는 않으나 비용으로 기록한다.
- 쓰지 않는 `oauth2`가 링크된다. SDK가 transport를 분리하면 사라질 비용이다.
- 의존 모듈이 둘에서 늘어난다. `go.mod`가 이 결정의 흔적이다.
- MCP와 `skills install`이 같은 쓰기 경계를 말해야 한다. 스킬 문서의 경계 문구가 진실원이고 도구 설명이 그것을 따른다.
- `serve`가 올 때 HTTP 전송을 여기에 붙일지 별도로 둘지 다시 본다.
