API 버전 정책 초안
2026-05-27 / 작성: 백엔드 담당

외부에 열어 둔 API를 바꿀 때 어떻게 할지에 대한 규칙 초안.
지금은 규칙이 없어서 바꿀 때마다 사용처와 일일이 조율한다.
사용처는 현재 세 곳(?). 목록을 정리해 둔 데가 없어서 세 곳이
맞는지부터 확인 필요.

1. 버전은 URL 경로에 표기한다. 지금 /v1/ 이 이 형태.
   다른 방식(헤더 등)은 검토하지 않음. 이미 늦었음.

2. 기존 동작을 그대로 두고 추가만 하는 변경은 버전을 올리지 않는다.
   다만 "기존 동작을 그대로"의 기준이 애매함.
   응답에 필드가 하나 늘어나는 것은 괜찮은가? (기준 필요)

3. 기존 동작을 바꾸는 변경은 새 버전을 만든다.
   옛 버전과 새 버전을 병행 운영한다.

4. 옛 버전은 폐기 예고 후 일정 기간 유지하고 없앤다.

5. 유지 기간은? 여기가 제일 정해진 게 없음.
   - 6개월? 한 달에 한 번쯤만 쓰는 사용처도 있어서 짧으면
     놓칠 수 있음
   - 12개월? 너무 길면 옛 코드를 두 벌 유지하는 비용이 계속 감
   - 사용처별로 다르게? 그러면 관리하는 누가 필요함

6. 폐기 예고는 어떻게 하는가?
   - 메일? 누가, 어느 주소로 보내는지 정해진 게 없음
   - 응답에 표시? (안내 헤더를 하나 넣는 방식)
   - 둘 다?
   - 사용처 담당자가 바뀐 경우 연락이 닿는 경로가 있는가? (의문)

7. 보안 문제가 있는 경우는 위 기간을 기다리지 않고 즉시 막는다.
   이견은 없을 것으로 보이지만 회의에서 확인 필요.

8. 버전을 없앤 뒤 옛 버전 호출은 어떻게 응답하는가.
   404? 안내 문구? (정해야 함. 안내 문구라면 어느 언어로)

다음 회의에서 정할 것
- 유지 기간 (6개월 / 12개월 / 사용처별)
- 폐기 예고 방법과 담당
- 필드 추가의 허용 기준
- 사용처 목록 확정과 관리자
- 없앤 버전의 응답 방식
