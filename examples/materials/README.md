# examples/materials/

실습 재료다. 수강생이 자기 위키에 집어넣을 **원재료**이며 위키가 아니다.

`examples/personal`과 성격이 다르다. 그쪽은 커맨드를 돌려서 나온 **결과물**이고 여기는 커맨드에 **집어넣을 입력**이다. engram이 이 디렉토리를 읽지 않는다.

전부 합성 자료다. 실제 조직, 실제 인물, 실제 제품이 들어 있지 않다. 저장소가 공개 예정이므로 그 경계를 지킨다([0024](../../docs/decisions/0024-public-boundary-and-private-directory.md)).

## 파일

| 파일 | 무엇 | 어느 커맨드로 |
|---|---|---|
| `회의-전사.txt` | 음성 회의를 STT로 돌린 결과 모양. 화자 분리가 어긋나고 군더더기가 섞여 있다 | `capture` |
| `기술문서-원문.md` | 외부 기술 블로그 글 전문 | `source` |
| `슬랙-스레드.txt` | 대화 로그 발췌. 성격이 다른 세 덩어리가 섞여 있다 | `capture` 여러 번 |
| `주간뉴스.txt` | 뉴스레터 한 통. 대부분 버릴 것이다 | `capture` 한 번 |

## 왜 이렇게 생겼나

**날것이어야 한다.** 정리된 요약을 주면 수강생이 그것을 복사해 붙이고 끝난다. 그러면 3단계가 가르치려는 것이 사라진다. `capture`는 아무것도 검사하지 않으므로 **무엇을 남길지 정하는 일이 전부 사람 몫**이라는 것이 그 단계의 내용이다.

**전사문에는 결론이 없다.** 회의가 가설 셋을 늘어놓고 각자 할 일을 나눈 채 끝난다. 실제 회의가 그렇다. 여기서 "결정된 것"과 "아직 모르는 것"을 갈라내는 판단이 4단계 승급의 재료가 된다.

**슬랙 로그는 한 덩어리가 아니다.** 배포 실패 원인, 설정 검사 방식, 기록이 안 쌓이는 이유 셋이 시간 순으로 섞여 있다. 통째로 하나 넣을지 셋으로 나눌지가 수강생의 판단이다.

**뉴스레터는 대부분 버릴 것이다.** 훑고 하나만 남기는 연습이다. 다 넣으면 inbox가 쓰레기가 된다.

## engram이 하지 않는 것

**STT는 engram의 일이 아니다.** `회의-전사.txt`는 전사가 이미 끝난 결과다. engram은 음성을 다루지 않으며 앞으로도 다루지 않는다. 전사는 사용자가 자기 도구로 하고 engram은 그 결과 텍스트만 받는다([0014](../../docs/decisions/0014-llm-boundary-agent-drives-binary.md)).

`docs/journeys.md`의 여정 2가 그 동선이며, 바이너리 밖이라 커맨드가 없다.

## 쓰는 법

실습 진행은 [docs/course/hands-on.md](../../docs/course/hands-on.md) 3단계가 진실원이다. 여기서는 순서를 적지 않는다. 두 곳에 적으면 어긋난다.
