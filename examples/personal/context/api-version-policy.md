# 외부 API 를 바꿀 때

## 왜 규칙이 필요한가

다루는 범위는 외부에 열어 둔 API 다. 지금은 규칙이 없어서 바꿀 때마다
사용처와 일일이 조율한다. 사용처는 세
곳으로 알고 있으나 목록을 정리해 둔 데가 없어 세 곳이 맞는지부터 확인해야
한다. 초안을 정해진 것과 미정으로 가르면 아래와 같다. 확정되는 대로
이 문서를 고쳐 간다.

## 정해진 것과 미정

| 항목 | 내용 | 구분 |
|---|---|---|
| 버전 표기 | URL 경로에 넣는다. 지금의 /v1/ 형태다. 헤더 방식은 검토하지 않았고 이미 늦었다 | 정해짐 |
| 추가 변경 | 기존 동작을 그대로 두고 추가만 하면 버전을 올리지 않는다 | 정해짐 |
| 동작 변경 | 기존 동작을 바꾸면 새 버전을 만들고 옛 버전과 병행 운영한다 | 정해짐 |
| 필드 추가 기준 | 응답에 필드가 늘어나는 것이 추가인지 동작 변경인지 기준이 애매하다 | 미정 |
| 옛 버전 유지 기간 | 여섯 달은 드물게 쓰는 사용처가 놓칠 수 있고 열두 달은 옛 코드를 두 벌 유지하는 비용이 남고 사용처마다 다르게 하면 관리자가 필요하다 | 미정 |
| 폐기 통지 | 메일을 누가 어느 주소로 보내는지 정해진 것이 없다. 응답에 안내 헤더를 넣는 방식과 섞는 안도 있다. 담당자가 바뀐 사용처에 연락이 닿는 경로가 있는지도 의문이다 | 미정 |
| 폐기 후 응답 | 옛 버전 호출에 404를 돌릴지 안내 문구를 돌릴지 정하지 못했다. 문구라면 언어도 정해야 한다 | 미정 |
| 보안 예외 | 보안 문제가 있으면 기간을 기다리지 않고 즉시 막는다. 이견은 없을 것으로 보나 회의 확인이 남았다 | 확인 필요 |

## 다음에 정할 것

회의에서 다룰 목록은 다섯이다. 유지 기간, 폐기 통지 방법과 담당, 필드
추가의 허용 기준, 사용처 목록 확정과 관리자, 없앤 버전의 응답 방식.
관리자를 정하는 항목이 두 개인 것은 우연이 아니다. 규칙은 문서로 정해지지만
지키는 것은 사람이기 때문이다. 사용처 목록이 확정되지 않으면 사용처마다
유지 기간을 다르게 주는 안 자체를 검토할 수 없다. 목록 확정이 다른
넷의 앞에 온다.

연달아 논의할 이웃 문서로 [[async-queue-review]] 가 있고 위키 전체의
자리매김은 [[index]] 가 잇는다.
