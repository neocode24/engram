# Pin 할 일 원장 규칙

## 위키 문서에서 할 일을 찾을 때 (`source: wiki`)

- 바뀐 `inbox/`, `sources/summaries/`, `sources/transcripts/`, `context/`, `exports/docs/`의 마크다운에서 맡은 일, 상대의 회신·자료·결정 약속, 기한이나 순서가 명시된 일을 찾는다. 배경 설명이나 이미 끝난 일은 새 항목으로 만들지 않는다. “검토해 보자”는 말만 있으면 제외하고, 담당이나 산출물이 적혀 있으면 검토한다.
- 항목 하나는 **누가 무엇을 끝내면 닫히는지**로 정한다. 담당이나 완료 조건이 다르면 나눈다. 같은 조건의 열린 항목(수락 전 포함)이 있으면 새로 만들지 않고 새 근거나 맥락만 보탠다. 문서에 없는 기한은 만들지 않는다. 담당이 명시됐는지(`stated`) 추정인지(`inferred`) 구분한다.
- 새 항목은 `via: extract`의 `add`로 요청한다. `evidence`에 문서 경로·절·날짜·단계·실제 인용문(`path, section, date, stage, quote`)이 하나 이상 있어야 한다. 같은 회의의 회의록과 전사가 모두 뒷받침하면 회의록을 먼저 놓고 각각에서 인용한다. 문서 이동만 있으면 근거 경로를 바꾸며 새 일로 세지 않는다.
- 적용하면 `todo` 항목과 `new_item` 제안이 함께 생긴다. 사람이 수락하면 제안 표시가 사라지고, 거절하면 항목을 뺀다. 나중에 문서에서 완료를 읽어도 상태를 직접 고치지 않고 인용과 함께 변경을 제안한다. 위키에서 온 일만 고를 때는 근거 링크 유무가 아니라 **항목의 `source`가 `wiki`인지** 본다.

## 직접 입력과 원장 쓰기

사람이 화면이나 명령에서 만든 일은 `source: command`다. `source`는 항목을 처음 만든 출처이고 `via`는 **이번 변경 요청**이 온 경로다. 미리알림도 출처 값은 단수 `reminder`, 요청 값은 복수 `reminders`다.

| `via` | 누가 무엇을 요청하나 |
|---|---|
| `web`, `command` | 사람이 화면 또는 명령으로 추가·수정하고 제안을 수락하거나 거절한다. 프로젝트 설명 변경은 명령만 받는다. |
| `extract` | 위키 추출기가 새 일, 근거·맥락 갱신, 관계, 상태 변경 제안을 낸다. 직접 완료하거나 삭제할 수 없다. |
| `reminders` | 미리알림에서 관측한 변경, 쓰기 확인, 삭제 판정을 전달한다. |
| `reaction` | 채널에서 사용자가 표시한 추가·수락·상태 변경·삭제 명령이다. |
| `judge` | 자동 판단이 새 일과 변경을 제안하거나 `enrich`로 정리하고 선행 관계를 요청한다. 사람의 반응이 아니다. |

원장의 항목·관계·제안에 쓰는 프로그램은 `scripts/pin/apply.py` 하나다. 다른 작성자는 변경 요청만 낸다. 명령은 `pin/intake/`에 요청 파일을 추가한다. 화면 대기열, 추출 결과 파일, 동기화가 읽은 변경도 같은 적용기를 거치며 모든 경로가 직접 intake 파일을 쓰는 것은 아니다. 요청에는 `id, at, via, op, args`와 필요시 `item, base_rev`를 쓴다. 같은 요청 id는 다시 적용하지 않으며 출처에 허용되지 않은 연산은 거절한다.

## 항목·관계·제안

| `pin/items/`의 항목 필드 | 뜻 |
|---|---|
| `id`, `rev`, `source`, `title` | 항목 번호, 변경 버전, 최초 출처, 제목. 버전 검사가 필요한 수정은 읽은 `base_rev`와 대조한다. |
| `work`, `owner`, `due`, `parent` | 프로젝트(미분류 `unsorted`), 담당과 판단 근거, 기한과 근거, 상위 항목. |
| `status`, `wait`, `since`, `created`, `closed_at` | 상태는 `todo`(할 일), `doing`(진행 중), `waiting`(대기), `hold`(보류), `done`(완료). 대기 사유는 `prior`(선행), `reply`(회신), `decision`(결정). 현 상태 시작일과 생성일·완료일을 구분한다. |
| `reminder`, `evidence`, `mentions`, `context`, `last_record` | 미리알림 연결, 근거, 언급·사람의 메모, 맥락(`why`, `now`, `next`와 작성 정보), 마지막 기록. |
| `locked` | 사람이 정한 칸을 자동 추출·정리가 덮어쓰지 않게 한다. 대상은 담당·프로젝트·기한·제목·맥락 전체 또는 개별 맥락 칸이다. |
| 선택: `rev_by`, `changes`, `origin`, `guess`, `unseen` | 마지막 버전을 바꾼 경로, 값 변경 이력, 채널 원문 정보, 정리 당시 프로젝트 후보와 글쓰기 결과, 새로 들어와 사람이 아직 확인하지 않았다는 표시(`true`만 쓴다). |

## 삭제

에이전트는 사용자가 지우라고 하지 않은 일을 지우지 않는다. 명령 `pin rm`은 `--yes`가 필요하다. 연결되지 않은 항목은 원장에서 바로 뺀다. 살아 있는 미리알림과 연결돼 있으면 두 걸음으로 지운다.
